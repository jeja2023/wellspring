# 分析建模：数据、模型与技战法

适用版本：`0.0.6`；当前迁移 head `0028`。完整范围和发布验证见 [0.0.6 版本说明](0.0.6-版本说明.md)。

当前统一入口为四字页面“分析建模”，页内用“数据建模 / 模型管理 / 技战法库”三个标签串联字段结构、分析规则与操作方法。这三者属于同一工作链，资料和权限仍分别管理。`0025` 新增资料表，`0026` 彻底删除证物相关运行能力、权限和八张业务表；执行删除前须停止服务并备份。

## 页面用途

| 页面 | 当前能力 |
| --- | --- |
| 数据建模 | 登记主题数据、实体或关系建模项目，维护编号、用途、字段名称/类型/必填说明和版本历史 |
| 模型管理 | 登记业务分析模型：碰撞规则、风险评分、分析流程；可关联建模项目并用手工样例验证 |
| 技战法库 | 保存线索核查、案件研判、综合分析的适用场景和操作步骤，可关联建模项目及业务模型 |

“模型管理”管理业务分析模型；AI 接口、Key 和模型 ID 仍从“智能研判 → 配置模型服务”弹窗配置。

页面复用统一标题说明、筛选、全宽表格、共享分页和表单弹窗。编号在本组织同类资料中唯一，创建后不改；记录仅本组织可见，关联不会扩大数据权限。没有数据时隐藏分页。

## 操作流程

1. 进入“分析建模 → 数据建模”，新增项目，填写编号、名称、用途和字段结构，保存草稿并查看配置。
2. 完成字段检查后，填写操作说明并启用项目。
3. 在“模型管理”标签新增模型，选择分类并关联项目，维护规则或流程配置，保存草稿。
4. 点击“样例验证”，提供手工字段对象数组，核对匹配、分值或流程步骤；验证后按需要启用模型。
5. 在“技战法库”标签登记适用场景和操作步骤，关联已准备的项目/模型，经核对后启用。

草稿可编辑或归档；启用后停止编辑，需要先停用回草稿。启用资料前，其关联项目/模型必须已启用。存在启用中的关联模型或技战法时，不能停用/归档上游资料。归档保留内容和版本历史，当前不提供删除或重新启用归档记录。

每次写入要求版本和幂等键；资料、版本快照及审计同事务提交。详情可以分页查看历次创建、修改、启停和归档快照。配置变化不会偷偷覆盖已经登记的历史版本。

## 配置示例

以下仅为合成字段示例，没有连接实际案件或人员数据库。

字段结构支持 1—50 个字段，类型为 `text`、`number`、`date`、`boolean`，字段名不重复：

```json
{"fields":[{"name":"record_count","type":"number","required":true}]}
```

碰撞规则支持 all/any 条件组合及 eq、ne、gt、gte、lt、lte、contains、in。当前是手工样例的条件匹配，不执行跨库身份碰撞：

```json
{"mode":"all","conditions":[{"field":"record_count","operator":"gte","value":3}]}
```

评分规则的每项 points 为 0—100 整数，总分不超过 100；仅按人工配置条件计算样例分值。缺失字段会显示 missing_fields，不生成完整分值：

```json
{"rules":[{"field":"record_count","operator":"gte","value":3,"points":40}]}
```

分析流程保存 1—20 个步骤，每步填写 name 和 description；样例验证返回步骤清单，不执行后台数据任务：

```json
{"steps":[{"name":"来源核对","description":"检查字段与统计口径"},{"name":"人工复核","description":"核验依据并记录意见"}]}
```

样例最多 100 条、总长 20000 字符、每条最多 50 个字段：

```json
[{"record_count":5},{"record_count":1}]
```

配置不接受或执行 Python、SQL、脚本表达式。样例不写入业务库或生成历史，只记录验证动作及模型版本；结果为规则验证，不作个人认定，也不自动调整案件、线索或业务状态。当前没有实际数据源连接、自动建模训练、跨库运行或定时分析服务。

## 权限和升级

各页面使用独立查询/维护权限：`modeling.read/write`、`models.read/write`、`tactics.read/write`。维护需同时授予查询权限；关联和启用时重新检查对应项目/模型的查询权限及组织。兼容业务角色补充这六项权限，自定义角色由管理员明确配置。

共享管理互斥保护资料启停和关联状态，防止并发停用上游时创建已启用依赖。版本事件在运行角色权限中只追加。默认不生成演示资料，也不把手工配置视作已批准的业务模型。

先备份，使用 `python migrate.py` 显式升级到 `0026` 后启动。旧三个导航名称恢复到“分析建模”；已保存项目、模型和技战法不合并数据、不丢失关联。

证物的前端组件、状态控制器、后端模型/路由、重量流水、分样、保管交接、盘点调查、专用测试和恢复核对代码均已删除。角色旧 `evidence.*` 授权由迁移清理；删除迁移不可逆，普通启动不会自动清理已有库。旧迁移文件保留用于把旧库升级到不含证物的最终结构，相关旧精度校验被封装在历史迁移内，当前运行层不再注册证物专用函数。通用数值类型仍用于污水浓度，通用审计保留历史轨迹。

验证使用独立合成 SQLite、账号及样例：组织隔离、读写授权、编号防重、幂等、配置验证、乐观锁、关联启停依赖和审计失败回滚，以及三个页面的创建、关联、样例和导航。实际结果见更新日志；未修改用户现有数据库。
