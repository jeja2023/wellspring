**1. P1：退出后旧请求可将上一账号的数据写入新会话——已复现。**

[workspace.ts](E:/wellspring/frontend/src/app/workspace.ts:64) 清空状态，但未让在途请求失效；[人员控制器](E:/wellspring/frontend/src/features/persons/controller.ts:11) 在请求返回后直接覆盖共享状态。A 发起人员查询，退出并切换 B，随后 A 的延迟响应返回，实际出现 token=user-B、people=[A-private]。这属于浏览器内的跨会话数据残留，不是服务端组织过滤绕过。

方案：在工作区维护会话版本号，请求发起时保存 token、会话版本和资源标识，回写前全部校验；退出时取消在途查询并递增版本。仅调用 AbortController 不够，还需要阻止已经进入回调的旧响应。验收应覆盖查询和写后刷新在退出、会话失效、重新登录前后的所有返回顺序。

**2. P1：快速切换证物会把 A 的流水显示在 B 的面板——已复现。**

[workspace.ts](E:/wellspring/frontend/src/app/workspace.ts:34) 的 loadEvents 无条件覆盖全局 events；[证物页面](E:/wellspring/frontend/src/features/evidence/EvidencePage.vue:9) 允许连续选择。先查 A，再查 B，让 B 先返回、A 后返回，结果 selected=b、events=[A-event]。业务人员可能据错误的对象上下文理解重量流水。

方案：loadEvents 显式接收 evidenceId、页码和请求序号，仅允许当前资源的最新响应提交状态；全局 loading 布尔值改为按操作或资源管理。验收使用两种返回顺序，并覆盖离开页面、分页和退出登录。

**3. P1：合并部署使用了存在已知漏洞的 Starlette 文件响应实现——版本与调用路径已确认。**

[requirements.txt](E:/wellspring/backend/requirements.txt:1) 固定 FastAPI 0.115.12；本地安装的 Starlette 为 0.46.2，FastAPI 元数据要求 Starlette >=0.40.0,<0.47.0。[combined_app.py](E:/wellspring/deploy/offline/combined_app.py:20) 使用 StaticFiles。官方 GHSA-7f5h-v6xp-fcq8 将 Starlette 0.39.0–0.49.0 列为受影响版本，恶意 Range 请求可能造成 CPU 消耗，0.49.1 修复该公告所述问题。[维护者公告](https://github.com/Kludex/starlette/security/advisories/GHSA-7f5h-v6xp-fcq8)

方案：联动升级 FastAPI 与兼容的 Starlette，并重新解析、锁定完整依赖。0.49.1 只是这一公告的修复下限，不代表所有后续公告均已修复；选定版本须再次检查完整公告。增加静态文件、Range、缓存头、API 异常响应回归。当前默认仅绑定本机，外部可达性受部署配置影响；本次没有对运行中的服务发起攻击。

**4. P1：离线包校验器在自身可信性尚未确认时被执行——已复现。**

[Windows 步骤](E:/wellspring/deploy/offline/WINDOWS.md:31) 核对 manifest 摘要后直接运行同包 verify_bundle.py。攻击者可以保留 manifest，替换校验器与 images.tar。校验器包含自身摘要也不能解决问题，因为替换后的程序可以直接返回成功。Linux 先验证 SHA256SUMS 也不充分，该文件没有被独立可信的 manifest 绑定，能够一起被替换。参考 [打包逻辑](E:/wellspring/deploy/offline/make_bundle.py:56)。

合成包验证结果：external_manifest_hash_still_valid=True，substituted_verifier_exit=0，actual_payload_matches_trusted_manifest=False。

方案：通过系统自带可信工具，依据已独立核验的 manifest 先校验 verifier，再执行它；或者使用独立安装的校验器和受信签名。验收必须包含“保持 manifest 不变、篡改校验器和镜像”的反向用例。

**5. P2：新版案件信息与原业务案件并存，但页面入口没有完整保留——代码确认。**

[CasePage.vue](E:/wellspring/frontend/src/features/cases/CasePage.vue:2) 仅挂载 CaseInformationPage，原 makeCase 和 CaseRelations 已无页面入口。Excel 导入写入 CaseInformation；证物登记、人员候选和线索关联仍依赖原 Case。用户在“案件管理”导入的记录不会成为下游可选案件。CSV 导入仍可创建原业务案件，因此不能说全部创建路径都已消失；案件关系页面的入口则确实缺失。

README 已明确两个模型独立，故不能把“独立模型”本身认定为设计错误。应先确认领域含义：若接警信息独立存在，就使用清晰名称，恢复业务案件及关系入口；若需要转案件，增加受权限控制、可审计、可追溯的显式转换关系。不要用编号相同就自动合并。验收贯穿“导入接警信息—转/建业务案件—登记证物—关联线索”。

**6. P2：SQLite 无法保证接口允许的全部重量精度——已复现，仅限 SQLite。**

[models.py](E:/wellspring/backend/wellspring/models.py:77) 使用 Numeric(20,6)，[分样更新](E:/wellspring/backend/wellspring/main.py:363) 在数据库内减余额。SQLite 浮点存储使合法边界值 99999999999999.999999 重读成 100000000000000.000000；再分样 0.000001，父余额没有减少，父子合计变成 100000000000000.000001。

方案：证物相关开发和验证统一使用 PostgreSQL；或者 SQLite 使用明确上限下的整数最小计量单位。业务上限需要业务确认。验收覆盖最大合法值、最小分样单位、多次分样守恒及并发竞争。此复现不能推导出 PostgreSQL NUMERIC 同样错误，也不表示日常重量均会产生该数量级误差。

**7. P2：运行角色的只追加权限遗漏重量事件表——代码确认。**

[init-runtime-role.sh](E:/wellspring/deploy/offline/init-runtime-role.sh:9) 对新表默认授予 UPDATE；[runtime.py](E:/wellspring/deploy/offline/runtime.py:29) 随后撤销多张历史事件表的修改权限，却没有 weight_events。运行角色因此仍有更新重量历史的权限。这是数据库防御边界缺口，未发现当前 API 提供直接改历史流水的接口。

方案：将 weight_events 纳入只追加清单，并用明确的表权限矩阵替代容易遗漏的逐项补丁。PostgreSQL 验收应使用实际 wellspring_app 角色，验证允许 INSERT、拒绝 UPDATE/DELETE，且正常业务仍可完成。

**8. P2：Windows CRLF 密码文件在建角色和应用连接时被解析为不同密码——代码确认。**

[init-runtime-role.sh](E:/wellspring/deploy/offline/init-runtime-role.sh:3) 的 shell 命令替换去掉尾部 LF，保留 CR；[runtime.py](E:/wellspring/deploy/offline/runtime.py:11) 去掉 CR/LF。Windows 文档允许 UTF-8 无 BOM、单行文件，没有排除 CRLF。符合文档的密码文件仍可能导致运行角色认证失败。

方案：统一密码文件的字节解析规范及实现，覆盖无换行、LF、CRLF、BOM、空值和多行。该项尚未在目标 Docker/PostgreSQL 环境端到端验证。

**9. P2：迁移提示可能让配置 PostgreSQL 的用户升级错误的 SQLite 库——代码确认。**

[start.py](E:/wellspring/start.py:36) 和 [README](E:/wellspring/README.md:81) 提示直接进入 backend 执行 Alembic，但根 .env 由 start.py、migrate_dev.py 加载，直接 Alembic 的 [db.py](E:/wellspring/backend/wellspring/db.py:5) 只读进程环境并默认 SQLite。未显式导出 DATABASE_URL 的用户照做后，PostgreSQL 仍未升级。

方案：面向本地开发统一使用根目录 migrate_dev.py，统一配置加载，并显示不含密码的目标数据库类型、主机和库名。验收同时覆盖根 .env、显式 DATABASE_URL 和默认 SQLite。

**10. P2：合法导入的类别值不能再用于筛选——已复现。**

[Search](E:/wellspring/backend/wellspring/case_information.py:16) 限制接警类型、结果最多 200 字符，但 [字段契约](E:/wellspring/backend/wellspring/case_information_schema.py:11) 允许 10000。导入 201 字符接警类型成功，搜索 options 返回该值，选择它后筛选返回 422。

方案：统一写入与筛选的字段约束，保证所有合法存储值均可被精确筛选。是否缩短类别字段需结合存量数据及业务定义，不能在前端静默截断。增加“导入—选项—筛选”契约测试。

**11. P2：初始化可创建正确密码也无法登录的账号——已复现。**

[bootstrap.py](E:/wellspring/backend/wellspring/bootstrap.py:13) 只检查密码至少 12 字符；[登录模型](E:/wellspring/backend/wellspring/main.py:29) 最多允许 256。257 字符密码可成功创建账号，登录返回 422。用户名也存在初始化与登录上限不一致。

方案：初始化、登录和未来账号管理共享账号字段规则，入库前返回明确错误。增加边界值测试，避免通过数据库错误或登录失败才暴露问题。

**12. P2：统一错误契约在前端被丢弃——代码确认。**

[client.ts](E:/wellspring/frontend/src/shared/api/client.ts:22) 只保留 message 和 status，丢弃 code、details、request_id。批量导入某一行字段过长时，后端虽然提供字段位置，用户仍只能看到“请检查填写的信息”；500 文案要求提供请求编号，前端却未保留它。

方案：ApiError 保留完整结构化错误，导入映射为 Excel 行号和中文字段名，错误面板提供可复制请求编号。不得将请求体或敏感原文作为排障日志默认输出。

**13. P2：翻页失败后页码与列表内容不一致——已复现。**

[workspace.ts](E:/wellspring/frontend/src/app/workspace.ts:62) 先修改页码再请求，失败不回滚。证物下一页请求失败后实际 page=2，但 items 仍是第 1 页；继续下一页会跳到第 3 页。

方案：先用候选页码发起请求，成功后一次提交页码、数据、总数和筛选条件；失败维持上一组一致状态。复用人员和情报模块已有的成功后提交模式，并结合请求序号防止乱序。

**性能与工程优化方案**

以下是有代码依据的优化方向。本次没有真实规模压测，因此不承诺延迟下降比例或容量上限。

| 方向 | 现状 | 建议与验收 |
| --- | --- | --- |
| 案件列表查询 | [case_information.py](E:/wellspring/backend/wellspring/case_information.py:63) 每次翻页执行总数、数据页、两项分组统计、两项 distinct，共 6 次业务查询，另有身份查询和审计写入。 | 列表、统计、筛选选项按需要分别加载；翻页不重复计算同一筛选条件的统计。统计仍需保持当前授权与筛选口径。用查询计数和数据库耗时验证。 |
| 列表数据体积 | 列表返回全部 20 个业务字段，多数字段允许 10000 字符；一页数据体积可能远超实际展示需求。 | 按页面实际需求建立列表摘要和详情契约，保留需要展示的列。记录响应字节数和首屏耗时后再决定，避免新增大量逐行详情请求。 |

| CSV 确认吞吐 | 每行 savepoint 和多次 flush 增加数据库往返。 | PostgreSQL 下评估批量插入和冲突回报，必须保留逐行结果、幂等与外层事务原子性；以 100/1000 行基准比较后决定是否值得改。 |
| 状态和错误处理 | 查询取消、超时、会话失效、loading、分页和请求序号分散管理。 | 在现有轻量模块上统一这些规则，保留“写入结果未知”与幂等重试语义。不要把超时直接当成服务端没有写入。 |

| 会话与幂等保留 | 会话仅登出时删除，幂等响应永久积累。 | 规定会话过期清理；幂等保留期必须与重试窗口、业务唯一性一起设计，不能简单清理后允许危险操作重复执行。 |
