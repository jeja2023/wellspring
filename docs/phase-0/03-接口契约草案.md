# 03 接口契约草案

当前 `0.0.7` 已移除全部 `/api/evidence` 接口，返回 404；本文旧版本小节仅保留历史契约。分析建模为一个页面入口和三个页内标签，接口与权限仍按原业务类型区分。

> 当前实现是开发接口 `/api`；正式接口目标为 `/api/v1`。本文件描述当前行为和迁移方向，不能替代最终 OpenAPI。

`0.0.5` 已补充接警完整详情与来源、污水监测、系统管理/角色授权和 `/api/ready`。最新范围、权限及升级见 [0.0.7 版本说明](../0.0.7-版本说明.md)；下列旧版本小节保留历史实现说明，精确字段以当前 FastAPI OpenAPI 和专题文档为准。

## 通用约定

- 认证：当前使用 `Authorization: Bearer <token>`；生产方式待确认。
- 内容类型：JSON 请求使用 `application/json`。
- 当前错误：统一使用 `code`、`message`、`details` 和 `request_id`。
- 当前列表：案件、证物和重量流水已支持授权范围内服务端分页及稳定排序，默认 20 条、最大 100 条。
- ID：使用不透明 UUID；不在 URL 放姓名、手机号、案情、令牌或完整文书。

## 路由评审规则

新路由必须说明资源／命令、HTTP 方法、权限、数据范围、幂等性、错误码、审计和兼容策略。普通 CRUD 使用名词和 HTTP 方法；领域命令才使用明确动作名，例如 `/submit`、`/sample`。不使用 `/getList`、`/doCase` 等技术实现型路径。

## 情报线索开发接口（0.0.2 开发验证）

所有接口使用现有服务端认证和组织范围；写请求要求 `Idempotency-Key`，不构成正式角色或字段权限。

| 方法 | 路径 | 开发验证行为 |
|---|---|---|
| GET | `/api/intelligence/assignees` | 返回本组织启用的前 100 个用户 |
| GET | `/api/intelligence/tasks/mine` | 获取当前组织、当前账号承办且未关闭的工单，按办理期限排序 |
| GET | `/api/intelligence/clues` | 按组织分页列出线索 |
| POST | `/api/intelligence/clues` | 创建线索草稿，包含标题、来源和摘要 |
| GET | `/api/intelligence/clues/{id}/detail` | 查询线索、工单和分页处理事件 |
| POST | `/api/intelligence/clues/{id}/review` | 按版本记录人工核验及说明 |
| POST | `/api/intelligence/clues/{id}/tasks` | 对已核验线索创建一个核查工单，指定同组织承办人，可填写 `due_date`（YYYY-MM-DD） |
| POST | `/api/intelligence/tasks/{id}/transition` | 按版本提交、退回或关闭工单；提交人与复核人分离 |

任务动作 `SUBMIT` 需提供核查结果；`RETURN` 和 `CLOSE` 需由非提交人执行，均需处理说明。完整状态及限制见 [情报线索范围草案](09-情报与线索范围草案.md)。

### 线索与案件关联（0.0.4 开发验证）

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/intelligence/clues/{id}/case-links` | 当前组织线索及案件双侧可见时，分页查看有效和已撤销关联 |
| POST | `/api/intelligence/clues/{id}/case-links` | `case_id`、`clue_version`、`basis`；需已核验线索与幂等键 |
| POST | `/api/intelligence/case-links/{id}/revoke` | `version`、`reason`；需幂等键，保留关联历史 |

关联仅使用通用关系，不等于并案或正式事实认定；相同线索和案件最多一个有效关联。

### 核查工单重分派（0.0.4 开发验证）

`POST /api/intelligence/tasks/{id}/reassign` 需要 `Idempotency-Key` 与 JSON：`version`（当前工单版本）、`assignee_id`（同组织启用用户）及 `reason`（非空原因）。仅 `OPEN` 或 `RETURNED` 可执行；相同承办人、过期版本、已关闭／待复核、跨组织或停用目标会被拒绝。响应返回更新后的工单；详细事件通过线索详情获取。该规则仅供开发验证。

### 线索筛选（0.0.4 开发验证）

`POST /api/intelligence/clues/search` 为只读查询，不需要幂等键；请求体包含 `keyword`（标题或来源，最多 100 字符）、`status`（`DRAFT`、`REVIEWED` 或 null）、`page` 和 `page_size`（最大 100）。服务端先限制当前组织，再进行字面包含匹配、状态过滤和稳定排序分页；摘要不参与匹配。返回现有分页结构并记录 `CLUE_SEARCH` 审计动作，审计不保存关键词。请求体可能仍被代理、监控或调试中间件记录，部署时必须禁止记录敏感请求体。该能力是开发用筛选，不等于已验收的中文全文检索或正式字段授权。

### 证物盘点与人员草稿（0.0.4 开发验证）

- `GET /api/evidence/{id}/inventory-observations`：组织范围内分页读取盘点观测。
- `POST /api/evidence/{id}/inventory-observations`：需要幂等键、`evidence_version`、十进制字符串 `observed_weight` 和 `note`；保存账面量、实测量及差异并递增版本，不改变余额。
- `GET /api/person-drafts`：组织范围内分页查询未核验人员草稿。
- `POST /api/person-drafts`：需要幂等键及 `name`、`source`；不自动核验或去重。

均为虚构数据开发接口，尚无正式岗位／字段权限和生产 RLS。

### 案件关系与人员筛选（0.0.4 开发验证）

- `GET /api/cases/{case_id}/relations`：校验当前案件及另一端组织范围，分页返回有效及历史关系。
- `POST /api/cases/{case_id}/relations`：需要幂等键、`target_case_id`、`relation_type`（`RELATED_TO`／`COOPERATE_WITH`）及 `basis`；禁止自关联和同类型正反重复。
- `POST /api/cases/relations/{relation_id}/revoke`：需要幂等键、`version` 和 `reason`，保留历史；不改变案件状态。
- `POST /api/person-drafts/search`：只读查询，JSON 包含 `keyword`、`page`、`page_size`；按组织过滤后匹配名称或来源。关键词不放 URL 或本地审计中。
- 盘点观测新增 `actor_id`、盘点版本及 UTC 时间展示。

以上仅供虚构数据开发验证；正式角色与跨组织授权尚未实现。

### 人员案件候选与工单复核队列（0.0.4 开发验证）

- `GET /api/person-drafts/{id}/case-candidates`：双侧组织范围过滤后分页读取候选与历史。
- `POST /api/person-drafts/{id}/case-candidates`：需要幂等键、`case_id`、`person_version` 和 `basis`；创建未核验候选，不确认身份或法律关系。
- `POST /api/person-drafts/case-candidates/{id}/revoke`：需要幂等键、`version` 和 `reason`；撤销保留历史。
- `GET /api/intelligence/tasks/reviewable`：分页列出同组织、提交人已知且不是当前用户的待复核工单；只返回定位所需字段。详情和复核仍需单独授权。

这些能力目前只具备开发组织过滤，不代表正式岗位、字段、专案权限或 RLS。

### 盘点差异调查（0.0.4 开发验证）

- `GET /api/evidence/inventory-observations/{id}/investigation`：组织范围内读取调查状态及分页事件。
- `POST /api/evidence/inventory-observations/{id}/investigation`：需要幂等键和启动 `note`；非零差异才能创建，每项观测最多一个调查。
- `POST /api/evidence/inventory-investigations/{id}/transition`：需要幂等键、`version`、`action` 和 `note`。调查人可提交；本组织其他用户可退回或复核说明。

上述为虚构数据开发流程；复核说明不代表正式审批、账面调整或差异结案。

### 开发辅助页面（0.0.4 开发验证）

- `POST /api/imports/case-csv-preview`：认证后提交 UTF-8 CSV 内容，限制 100 KB 和 1000 行，校验表头、字段长度、文件内重复及公式前缀；仅返回预览及摘要，绝不保存文件或导入案件。未做来源策略与现有数据差异对比；不支持 Excel。
- `GET /api/audit/mine`：仅返回当前主体在当前组织的本地审计，分页读取本身追加审计；不构成管理员审计中心或防篡改保护。
- `GET /api/ai/status`：只报告未接入，不接受文件或生成结果；OCR／模型、任务、核验和正式提交尚未实现。

### 案件 CSV 暂存与新增草稿（0.0.4 开发验证）

- `POST /api/imports/case-batches`：需要幂等键、`source` 与 CSV `content`；保存固定映射 `DEV-1`、UTF-8 文本摘要及逐行格式／本组织编号冲突结果。原始文件不保存，逐行解析值及原因保存在数据库。
- `GET /api/imports/case-batches` 与 `GET /api/imports/case-batches/{id}`：仅创建者且同组织可分页查看批次及结果。
- `POST /api/imports/case-batches/{id}/cancel`：需要幂等键，只能取消待确认批次，暂存记录保留。
- `POST /api/imports/case-batches/{id}/confirm`：需要幂等键；仅预览为新增且确认时编号仍未占用的行创建案件草稿，冲突和错误行保留结果，不更新既有案件。批次占用、行结果、业务写入、审计和幂等结果同一事务提交；任何非编号冲突错误回滚整批。

这只是虚构数据技术验证，限定 100 KB／1000 行、固定模板和单次事务。来源编号作用域、Excel、字段映射策略、已生效批次补偿更正、分组处理、正式权限、恶意文件检查和 PostgreSQL 并发尚未完成；不得接入真实业务。

### 证物保管交接（0.0.4 开发验证）

- `GET /api/evidence/{id}/custody`：读取开发保管人、待接收交接和分页事件。
- `GET /api/evidence/{id}/handovers`：分页读取本组织交接历史。
- `POST /api/evidence/{id}/custody/baseline`：幂等键、`evidence_version`、`note`；由当前用户建立一次开发基线。
- `POST /api/evidence/{id}/handovers`：幂等键、`custody_version`、`to_user_id`、`note`；只有当前开发保管人可发起。
- `POST /api/evidence/handovers/{id}/respond`：幂等键、交接 `version`、`action`（`ACCEPT`／`REJECT`）和 `note`；仅指定接收人操作。接收前及拒收后原责任不变。

该切片仅模拟本组织单件交接，未实现封条、地点、附件、实物逐项核验、审批、异常锁定及正式岗位权限，不可用于真实业务。

JSON 写入使用原有幂等键、版本与结构化错误契约，具体动作/字段以当前 OpenAPI 为准。地图经纬度须成对，来源必填，当前只接受 WGS84；业务审计与状态变化同事务。专题的开发阶段历史数字不替代 [0.0.7 发布复核](../0.0.7-版本说明.md)。


### 0.0.7 审计查询增量

`GET /api/audit/mine` 新增 `action`（中文名称或动作代码，最长 80）、`object_id`（标识包含匹配，最长 36）、`start_date`、`end_date`（YYYY-MM-DD）；仅查询当前主体历史，不按新组织丢弃本人旧组织记录，也不因知道其他对象标识而扩大范围。日期按 Asia/Shanghai 的自然日计算，结束日期使用下一日零点的排他上界，起止倒置或超出范围拒绝。

`POST /api/admin/audit/search` 保留管理员授权、账号/动作筛选，`action` 兼容原动作代码并支持中文名称。两个接口的 `page_size` 默认值由 20 改为 15，仍接受 1—100 的显式值；响应每项保留 `action`，增加中文 `action_name`，不修改持久化动作代码或历史流水。未知历史代码的描述为“其他操作”，前端不直接显示原代码。两页的查询失败均保留最后成功的结果、页码和已应用条件，不将当前输入误表示为已应用筛选。

### 0.0.7 地图配置与用语兼容

`GET /api/geography/config` 新增 `tile_coordinate_system`（WGS84/GCJ02）、`min_zoom`、`max_zoom`、`initial_view`（底图原生经纬度及级别），错误配置返回 `MAP_CONFIG_INVALID`。瓦片 API 路径不变，按顺序支持磁盘 `z/x/y.png` 和 `z/x/y/tile.png`，保持认证、根目录范围及 2MB 大小检查。业务定位请求的 `coordinate_system` 仍只接受 WGS84，高德显示/选点在前端离线近似换算。

案件、人员、线索、分析资料、检测及研判结果的中文名称调整不改变 ID、状态值、幂等操作名或 API 路径。AI 统计解读和个人历史弹窗使用现有 `/api/ai/runs`，没有新增对外模型接口、免权限入口或业务事实写入。
