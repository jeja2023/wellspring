# 02 数据字典（开发基线）

当前 `0.0.6` 结构以迁移 head `0028` 和当前模型为准；证物相关表已由 `0026` 删除。下列旧版本表结构是历史参考，不能用于当前功能或新建模型；完整移除说明见[分析建模说明](../建模模型与技战法.md)。

> 当前内容依据 `backend/wellspring/models.py` 和初始 Alembic 迁移整理。生产字段、敏感级别、保留期限和来源权威性仍需业务／安全确认。

`0.0.5` 增补接警台账、污水监测、接警来源关系、角色与账号管理及精确重量存储，迁移 head 为 `0021`。本文件旧版本小节保留历史结构，新增模型以 `models.py`、`wastewater_models.py`、`intake_models.py`、`access_models.py` 及迁移为准；`0.0.5` 历史结构见原版本说明，最新范围和升级见 [0.0.6 版本说明](../0.0.6-版本说明.md)及其专题链接。

## 0.0.6 新增及调整的现行结构

| 表 / 模型 | 用途与关键约束 |
| --- | --- |
| `ai_services`、`ai_runs` | 单一模型配置、版本和检查状态；Key 仅保存随机引用。任务按账号/组织隔离、保存状态和待核验结果，不保存发送原文；生成和交付前复核权限 |
| `clue_import_batches`、`clue_deliveries`、`clue_delivery_events` | 导入来源/摘要、按组织树的下发快照、承办、期限、反馈和逐级复核历史；线索/事件增加关联字段，重要性限制随流转继承 |
| `analysis_assets`、`analysis_asset_events` | 分为建模项目、业务模型、技战法的本组织资料、配置、关联、状态和版本快照；编号在组织/类型内唯一 |
| `person_drafts` 扩展 | 保留旧稳定 ID，增加证件、出生日期、联系方式、责任单位/人员和身份核验字段；未获完整身份权限不返回原值 |
| `person_records`、`person_events` | 吸毒相关、正式案件、措施、检测/随访分条登记；来源、依据、核验、更正链及实际执行日期/状态；事件只追加 |
| `person_tasks`、`person_transfers` | 人工/记录生成的待办及确认交接；同一人只能有一项待接收移交，接收前不共享完整档案 |
| `places`、`place_inspections`、`place_incidents`、`place_events` | 本组织唯一场所编号、管理依据/复核日期、巡查整改、具体事件及独立核验/处置；场所历史只追加，事件可显式关联线索草稿 |
| `geo_locations`、`geo_location_events` | 只允许场所/场所事件/污水采样点类型；业务记录唯一定位，WGS84 经度/纬度成对填写或清空，版本冲突与来源历史；不保存人员坐标或轨迹 |
| `organizations.unit_type` | 市局/支队、分局/大队、派出所、其他；旧单位保持其他，不按名称猜测 |
| 证物八表 | `0026` 明确删除，以下旧版本章节只作迁移溯源，不能视作当前表结构 |

精确列定义以 `ai_models.py`、`intelligence_models.py`、`analysis_models.py`、`person_models.py`、`place_models.py` 及 `0022`—`0028` 为准；迁移编号不等于产品版本。模型凭据和离线底图是数据库之外的受控文件，备份要求见各专题文档。

## 当前不变量

- 案件编号在同一组织内不得重复。
- 用户只能通过服务端账号组织访问案件和证物；客户端传入的组织信息不参与授权。
- 证物余额不能因分样操作变为负数；父对象扣减和子对象增加必须使用同一操作 ID。
- 追加流水不能通过普通更新或删除抹去历史。
- 当前数据仅用于虚构开发验证，不构成正式证物账目。

## 待补字段（生产设计前确认）

来源系统、记录版本、数据分类、敏感级别、案件关系、审批依据、状态事件、保管位置、交接双方、附件对象版本、保留／冻结状态、字段更新责任人和审计完整性摘要。

## idempotency_records（0.0.1）

按主体、操作与幂等键唯一约束保存请求摘要、结果状态和结果引用；与业务变更和审计同事务提交。请求摘要绑定当前组织，重放前先验证账号与目标对象的当前访问权限。记录目前尚无自动清理，生产保留期限和独立保护待确认。

| 字段 | 用途 |
|---|---|
| `id`、`actor_id`、`operation`、`idempotency_key` | 唯一标识及主体／操作范围 |
| `request_hash` | 规范化请求和组织范围的摘要 |
| `status`、`status_code`、`response_json`、`resource_id` | 处理结果及重放响应 |
| `created_at`、`completed_at` | 记录和完成时间 |

## 开发验证情报数据（迁移 0003）

- `clues`：组织、标题、摘要、来源、创建者、状态、版本、时间。
- `investigation_tasks`：线索、组织、目标、承办人、可选办理期限（`due_date`）、状态、最后提交人、最新结果、版本和时间；当前一个线索最多一个工单。
- `intelligence_events`：线索、可选工单、组织、操作者、动作、前后状态、意见、当次结果和时间；提交、退回、复核均追加记录。

这些字段及状态仅为虚构数据开发验证。跨区权限、正式数据分类、截止时间、重分派及保留政策未确定。

## 线索案件关联（迁移 0005，未发布）

`clue_case_links` 保存组织、线索、案件、依据、有效状态、创建者／时间、版本及撤销人／时间／原因；部分唯一索引限制同一线索和案件只有一条 `ACTIVE` 关系。`intelligence_events.related_link_id` 保存可空关联标识以回溯对应事件，当前由应用维护并无数据库外键。

## 工单重分派事件（迁移 0006，0.0.3 开发验证）

`intelligence_events.assignee_before_id`、`assignee_after_id` 是可空的人员标识字符串，由应用维护，当前没有数据库外键；新建工单事件记录初始承办人，`REASSIGN` 事件记录前后承办人。迁移前事件保留空值，禁止从当前状态推断历史。

## 证物盘点观测与人员草稿（0.0.4 开发验证）

- `evidence_inventory_observations`（`0007`）：组织、证物、账面量、实测量、差异、盘点时证物版本、说明、操作者和时间。创建只递增证物版本，不改余额或生成重量调整流水；差异调查、复核与审批尚未实现。
- `person_drafts`（`0008`）：组织、名称、来源、`UNVERIFIED` 核验状态、创建者、时间和版本。仅为开发草稿，不按姓名去重、不包含身份证件或法律状态。

## 案件关系（迁移 0009，0.0.3 开发验证）

`case_relations` 保存组织、规范化后的两端案件、关系类型、有效状态、依据、版本、创建及撤销信息。当前仅支持对称的 `RELATED_TO`、`COOPERATE_WITH`，部分唯一索引防止同类型有效关系正反重复；撤销保留原关系。`case_relation_events` 追加创建／撤销操作、状态、原因、主体和时间。派生、并案及拆分尚未实现。

## 人员案件候选（迁移 0010，0.0.3 开发验证）

`person_case_candidates` 保存组织、未核验人员草稿、案件、依据、有效状态、版本及创建／撤销主体时间；部分唯一索引禁止同一人员与案件出现多个有效候选。`person_case_candidate_events` 保存创建、撤销及原因。候选不代表正式案件人员关系，不改变人员核验状态或案件状态。

## 盘点差异调查（迁移 0011，未发布）

`inventory_investigations` 保存盘点观测、调查人、状态、最后提交人和版本；`inventory_investigation_events` 追加启动、提交、退回及复核说明。仅非零差异可启动调查，每条观测最多一项调查。复核说明不改变证物重量或生成重量调整流水；正式差异审批、记账和岗位权限未实现。

## 案件 CSV 开发暂存（迁移 0012，未发布）

`case_import_batches` 记录组织、发起人、用户填写的虚构来源、内容 SHA-256、固定映射版本、状态及时间；`case_import_rows` 保存批次、文件行号、截取后的字段、预览分类、处理结果、原因及新建草稿标识。原始文件和完整无效行不保存；这不满足正式来源保全与对账要求。

## 保管交接（迁移 0013，未发布）

`evidence_custody` 保存每个证物的开发保管人和版本；旧证物不会自动推定保管人，须人工建立开发基线。`custody_handovers` 记录交出人、接收人、待接收／已接收／已拒收状态、说明和版本；部分唯一索引限制每件证物仅一个待接收交接。`custody_events` 追加基线、发起、接收或拒收事件。所有交接不修改重量余额。
