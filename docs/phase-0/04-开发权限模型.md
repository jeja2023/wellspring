# 04 开发权限模型

> 这是个人开发阶段的最小权限假设，不是生产权限矩阵。

## 当前模型

| 主体 | 当前可做 | 当前限制 |
|---|---|---|
| 开发账号 | 登录、查看和创建本组织开发案件／证物、登记分样、查看相关流水 | 仅虚构数据；没有完整角色矩阵、字段、专案、双人复核和正式审批 |
| 初始管理员 `admin` | 有管理员标识，可访问管理员状态接口和开发用系统操作日志 | 目标定位为超级管理员；全部应用权限、账号管理及角色分配尚未实现 |
| 未登录 | 健康检查 | 不能访问业务接口 |
| 已禁用账号／过期会话 | 无业务访问 | 服务端拒绝 |
| 其他组织账号 | 只能看到自己的组织 | 当前为组织过滤，不等于生产 RLS |

## 开发阶段硬规则

- 所有业务接口必须依赖服务端当前用户，不信任客户端提交的 `org_id`、角色和权限结论。
- 跨组织对象即使 ID 已知也应按“记录不存在或无权访问”处理，避免对象枚举。
- 新增敏感字段默认不返回，除非明确写入数据字典和展示权限。
- 开发数据不能导出到项目外部，也不能通过日志、异常、截图和 URL 泄露。
- 高风险功能先在虚构数据上验证状态、权限和审计，再考虑接入真实系统。

## 生产前待建模型

认证来源、角色、组织／辖区、案件／专案授权、字段遮盖、附件权限、临时授权、撤权窗口、紧急访问、运维与业务分离、RLS 和独立审计归集均待业务／安全确认。

具体候选角色、权限矩阵和实现顺序见 [角色与权限设计草案](10-角色权限设计草案.md)。
