# 清源 Wellspring 正式开发前准备清单（个人独立开发版）

> 项目版本：`0.0.3`（开发验证基线）
> 适用对象：当前个人独立开发、仅使用虚构数据的阶段  
> 上位依据：[总体设计与实施方案 v2.5.0](../清源·禁毒全流程协同平台v2.5.0.md) 及 [开发与交付规范](开发与交付规范.md)  
> 当前结论：可以继续进行个人技术验证和 MVP 编码，但不能接入真实业务数据或宣称生产可用。

## 1. 精简原则

个人开发阶段只保留会直接影响代码正确性、安全性、可维护性和后续扩展的准备工作。多人项目才需要的会议、签字、采购、合同、培训和正式移交，暂时放到后置清单，不阻塞本地 MVP 开发。

不能省略的内容包括：

- 本轮功能范围和明确的非目标。
- 虚构数据边界、权限假设和敏感数据禁止规则。
- 数据模型、状态、接口输入输出和迁移方案。
- 错误、空状态、权限失败和并发冲突处理。
- 基础测试、依赖锁定、密钥保护和可恢复的开发数据。
- 影响未来生产的设计决策记录。

个人开发阶段可以使用一份自己的决策记录代替多人评审，但每项决策都应写明日期、假设、影响和后续复核点。

## 2. 开始下一阶段开发前必须完成

### 2.1 范围和任务

- [ ] 写清本次要实现的一个可验证目标，以及明确不实现的内容。
- [ ] 将功能拆成页面、接口、数据、权限和测试任务；不要一次扩展多个无关业务域。
- [ ] 先搜索现有代码，确认是否已有组件、接口、查询、样式、服务或测试可以复用。
- [ ] 记录会改变数据库、接口、权限、文件、任务或用户可见行为的影响。
- [ ] 复杂或高风险规则先做一个小样例和测试，再扩展到页面和完整流程。

### 2.2 数据和安全

- [ ] 只使用虚构数据；禁止把真实案件、人员、证物、文书、账号或导出文件放入个人开发环境。
- [ ] 不把密码、Token、数据库连接串、证书或密钥写入代码、日志、截图和提交记录。
- [ ] 每个新增接口都在服务端验证身份、组织／数据范围、输入长度、枚举、版本和业务前置条件。
- [ ] 不信任前端传入的 `org_id`、角色、文件路径、状态或权限结论。
- [ ] 上传文件使用暂存目录、类型／大小限制和清理机制；下载通过受控接口。
- [ ] 记录关键写操作的最小审计信息；日志不写入敏感原文和完整输入。

### 2.3 数据库和接口

- [ ] 数据库结构通过 Alembic 迁移修改，不直接依赖手工改表。
- [ ] 每个核心对象有明确主键、唯一范围、状态、来源、创建时间和必要的版本字段。
- [ ] 正式事实、流水和更正使用追加事件或冲正，不能靠覆盖或删除历史。
- [ ] 需要重复提交的写操作先设计幂等键；需要并发保护的写操作使用版本号、条件更新或事务锁。
- [ ] 列表接口使用服务端过滤、排序和分页；当前开发也不能用前端全量读取代替正式方案。
- [ ] 接口错误返回安全、可执行的中文提示，不返回 SQL、堆栈、绝对路径或内部地址。

### 2.4 页面和交互

- [ ] 复用已有设计令牌和共享组件；不为单个页面建立独立按钮、表格、输入框或弹窗体系。
- [ ] 页面至少覆盖加载、空数据、无结果、失败、无权限、成功和重复提交状态。
- [ ] 高风险操作显示影响范围和明确动作名称；不能只依赖隐藏按钮保护接口。
- [ ] 表单有标签、单位、必填提示、字段错误和服务端错误保留；提交失败不能清空输入。
- [ ] 页面和 API 使用统一命名、分页、路由和 URL 规则。
- [ ] 新页面支持键盘焦点和基本的文字对比度检查。

### 2.5 验证和记录

- [ ] 新增业务规则至少有一个正向用例、一个失败用例和一个权限反向用例。
- [ ] 涉及金额、重量、数量、状态、权限或文件的功能增加数据一致性测试。
- [ ] 运行受影响的后端测试、迁移检查和前端构建；未运行的检查写明原因。
- [ ] 更新 API、数据字典、规范或更新日志中受影响的部分。
- [ ] 提交前删除临时按钮、调试输出、测试数据、死代码和无效注释。

## 3. 当前项目的最小启动顺序

按当前 `0.0.3` 工程，建议依次完成：

1. 将集中式 `App.vue` 按 `app`、`shared` 和 `features/cases`、`features/evidence` 拆分。
2. 已完成开发接口分页、统一错误结构和写操作幂等基础；继续验证 PostgreSQL 并发和撤权。
3. 将开发用组织过滤逐步替换为明确的角色、数据范围和服务端权限依赖；生产 RLS 在 PostgreSQL 环境中单独验证。
4. 扩展证物流水前先完成交接、送检、实际消耗、退样、盘点和销毁的状态与测试设计。
5. 建立最小 CI：后端测试、Alembic 检查、前端类型检查和生产构建。
6. 保持所有数据为虚构数据，完成一个可重复的本地初始化和清理流程。

## 4. 可以暂缓到团队协作或生产准备阶段

以下事项当前个人开发不必阻塞每个功能，但在接入真实数据、交付他人或上线前必须补齐：

- 多人 RACI、正式会议纪要、跨部门签字和供应商付款里程碑。
- 统一身份平台接入、正式账号生命周期、专案授权和紧急访问审批。
- PostgreSQL 非特权运行角色、RLS 全量策略、独立审计归集和正式撤权窗口。
- 生产网络拓扑、HTTPS 证书、对象存储集群、跨网交换和正式备份介质。
- SBOM、离线制品仓库、许可证审查、漏洞响应和供应链交付包。
- 压测容量、RPO／RTO、完整灾备演练、值班告警和故障应急手册。
- 历史数据清洗、正式导入、用户培训、试运行、运维交接和上线验收。
- OCR／LLM 生产模型、脱敏评测集、质量阈值、模型回归和独立算力环境。

“暂缓”不等于取消；应在版本或任务中保留责任和触发条件，防止个人 MVP 直接演变成未经评审的生产系统。

## 5. 个人开发完成定义

一个功能可以在个人开发阶段标记为完成，至少需要满足：

- 目标范围已实现，非目标没有伪装成已实现。
- 页面、接口、数据和状态行为一致。
- 服务端权限、输入校验、错误处理和关键审计已存在。
- 正向、失败、权限反向和必要的一致性测试通过。
- 数据库迁移可以从空库重复执行，开发数据可以初始化和清理。
- 没有真实敏感数据、密钥、临时调试代码和未说明的已知问题。
- 更新日志记录本次变化、验证结果和剩余限制。

个人开发完成不等于生产上线完成。进入正式试点前，必须切换到完整阶段 0 和生产验收清单。

## 7. 正式开发或生产前再开启的清单

当项目出现以下任一情况时，应从个人精简清单切换到完整阶段 0：接入真实数据、交给其他开发者、连接外部系统、启用 OCR／LLM 生产处理、需要跨组织访问、准备部署到内网生产环境、涉及正式证物或法律状态，或需要对外承诺交付日期和验收结果。
