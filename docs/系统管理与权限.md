**用户、角色、权限和组织管理**

适用产品版本：`0.0.5`；数据库迁移 head `0021`。完整变更与本次版本验证见 [0.0.5 版本说明](0.0.5-版本说明.md)。

本轮在现有账号与组织模型上补齐可操作的系统管理页面及服务端权限校验，保留既有业务数据。独立“数据导入”菜单已取消；案件CSV的暂存、逐行核对、确认/取消和批次记录整合到“案件管理 → 批量导入 / 导入记录”，接警Excel仍在“接警信息”。

| 页面 | 当前能力 |
| --- | --- |
| 用户管理 | 分页查询、创建、启停、调整组织/角色、授予/撤销超级管理员、重置密码；账号名创建后不改；不显示密码哈希或旧密码 |
| 角色管理 | 创建普通用户/普通管理员角色，维护名称、代码、职责、启停与权限；超级管理员作为受保护账号标识，不做可任意复制的普通角色 |
| 权限管理 | 固定系统权限目录，按角色、名称/代码、业务模块及已选状态筛选；权限分列表格、连续序号与共享分页；给角色勾选、撤销并保存，未知代码拒绝 |
| 组织管理 | 创建、改名、上级归属、启停、分页查询；防重复名称、循环层级；有启用直属账号或子组织时拒绝停用 |

用户、角色和组织列表均采用全宽台账，新增与编辑由工具栏或行内按钮打开统一弹窗；密码重置也在弹窗完成。人员、案件、线索、证物、污水录入及CSV新建导入批次沿用同一弹窗组件。保存成功关闭，保存失败保留当前输入；提交中锁定表单和关闭操作，支持键盘取消、回到原按钮及窄屏滚动。

各页面名称仅在顶部栏显示，内容区不再重复显示页面标题或“用户管理列表”等同义标题。用户表的“所属组织”“角色”与角色表的“角色代码”“角色级别”各自独立成列；数据保持单行，宽度不足时在表格内横向滚动。

权限管理复用其他管理页的单卡片、输入框、按钮、表格边框和分页样式。顶部横向选择角色并查询名称/代码、模块，可切换“仅看已选”；表格逐行展示序号、业务模块、权限名称、权限代码、配置范围和授权状态。底部是常规保存/撤销区，显示新增、移除和未保存项数。筛选及分页保留授权草稿，切换角色前可继续编辑或明确放弃；缺少模块查询权限时提示所缺项目并禁止保存。

导航顺序为“人员档案 → 智能解析 → 操作记录 → 系统管理分组”；“智能解析”仍只显示未接入状态，位置调整不新增模型解析能力。

**授权边界**

- 超级管理员可维护全部账号、角色、组织及系统日志。普通管理员只有获得 `system.users` 才能管理本组织普通账号；不能管理管理员或超级管理员，不能跨组织调动账号，也不能分配超出自身权限的角色。角色和组织配置只允许超级管理员，防止借配置绕过委派边界。
- 每账号当前分配一个角色。普通用户角色不能包含系统管理权限，普通管理员角色可配置业务权限和本组织用户管理。业务操作授权必须同时有对应查询权限。转办接警、查看案件来源和跨模块关联还会组合校验相关业务查询/写入权限。
- 所有现有受保护业务接口都会核对当前有效账号及角色；前端菜单按服务端权限显示，常用写入表单按权限隐藏，直接构造请求也会被服务端拒绝。未纳入模块映射的新路径默认拒绝普通账号；已纳入模块的新操作仍按该模块的查询/办理规则校验，新增特殊操作需同步补充权限映射与反向测试。
- 本轮权限颗粒度主要是模块查询、模块办理及专门导入/导出等操作；证物双人交接、污水不同账号复核和工单承办约束继续执行。还没有配置字段级脱敏、专案授权、跨组织共享或法规意义上的岗位审批矩阵，这些不能用一个“角色”选项替代。
- 组织层级只维护归属，不授予上级查看下级业务数据。超级管理员对系统配置的全局权限也不自动修改既有业务查询范围：接警台账保持原有管理员跨组织查看，其他业务及接警转办等仍按现有组织校验。

**账号安全与生效**

密码须12–256字符，重置使用操作者输入的新密码，不查询或回显旧密码。页面新增“修改密码”，用户验证原密码后可修改，成功后全部旧会话失效。重置后的临时密码需受控交付；本轮未实现首次登录强制改密、MFA或统一身份认证。

停用、改变账号角色或组织、重置密码会删除该账号的旧会话；角色权限/状态变更会撤销受影响普通账号的会话并增加账号版本。已有会话在下一次请求被拒绝，前端清除会话；已经进入执行的业务事务不会被强行回滚。后台管理修改通过全局数据库互斥行串行执行，锁后重读操作者与会话，避免并发撤权后继续授予权限。

禁止停用或降级最后一个处于启用组织、可登录的超级管理员；PostgreSQL并发验证保证两个超级管理员同时停用自己时仍至少保留一个。组织停用前必须处理启用中的账号和下级组织，不提供静默批量停用或删除组织/角色/用户的能力。修改组织归属不会搬迁该用户历史创建的案件等记录。

新增管理写入使用幂等键、版本冲突校验和同事务审计。密码仅存带盐哈希，幂等比较使用密码摘要而不存明文；日志不打印输入密码和令牌。后台数据查询与配置变更记录审计，仍不是独立外部防篡改审计系统。

**升级与旧账号**

新增 `0021`，扩展用户/组织字段并新增角色和管理互斥表；原有非超级管理员迁入“业务用户”兼容角色，保留原开发业务范围；原有超级管理员标识保持。兼容角色可由超级管理员重新配置，新增用户必须明确选择启用角色；新增组织不含默认账号或密码。此迁移不向普通账号授予系统管理权限，不自动合并组织或搬迁业务数据。

停止旧程序后运行 `python start.py`，按受控规则备份并升级；遇到更早的人工迁移边界，先核对再运行 `python migrate.py`。离线环境运行独立 migrate 任务，重新应用运行账号的表权限。`0021` 默认允许启动迁移，不代表正式生产权限验收完成。

验证使用合成SQLite和隔离PostgreSQL：普通用户直调写接口/管理接口拒绝、普通管理员跨组织/越级授予拒绝、撤权和密码重置旧会话失效、审计失败完整回滚、最后管理员并发保护、组织循环/使用中停用拒绝、完整迁移链及模型一致性。浏览器覆盖组织/角色/用户创建、权限配置、重置登录、只读菜单与接口拒绝、案件导入入口及既有业务流程。

系统管理初次实现阶段的历史结果：后端152项、前端38项通过；6条浏览器端到端通过，构建后的Docker镜像也通过相同6条流程及就绪、静态资源和安全头检查。类型检查、生产构建、`git diff --check` 通过。测试客户端仍有一项已知httpx弃用提示，按需加载ExcelJS有体积提示，均未导致检查失败。实际数据库验证使用隔离PostgreSQL 18，未升级用户现有数据库；临时实例已停止，验证容器已清理。
