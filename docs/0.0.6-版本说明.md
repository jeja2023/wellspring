# 清源 Wellspring 0.0.6 版本说明

发布日期：2026-11-11。状态：**本地开发验证版本**。本版本汇总 `0.0.5` 之后全部未发布修改，数据库 head 为 `0028`；不表示生产部署、真实模型/地图接入或正式业务验收。历史版本和旧验证数字不改写。

## 本次功能与界面

| 范围 | 最终行为 |
| --- | --- |
| 数据大屏 | 按当前组织和获准模块汇总接警、案件、线索、人员及污水监测，支持 7/30/90 天新增趋势、状态分布、每日数据、手动/周期刷新及全屏；当前不再统计证物 |
| 智能研判 | 接入可配置的 OpenAI 兼容文本服务，提供摘要、要素提取、资料问答和授权统计解读；结果作为个人待核验草稿，支持任务历史、取消、复制/下载，不自动写入业务事实 |
| 模型配置 | 在“智能研判 → 配置模型服务”共享弹窗填写根地址、API Key、模型及参数；可获取模型 ID、手动填写、测试未保存配置、保存及检查连接。Key 不回显，数据库只保存受控目录的随机引用；支持保留、替换、清除及环境回退 |
| 情报线索 | 手工/Excel 收录，核验后按组织层级下发、接收承办、转交、处置、结构化反馈、退回补充及逐级复核办结；本级/收到/我下发/导入记录分区及状态/逾期筛选。重要线索限制向下继承，未办结下级反馈阻止上级汇总 |
| 分析建模 | 将数据建模、模型管理、技战法库合并为四字入口，页内三个标签保留资料、关联、版本及独立权限；支持声明式规则配置和手工样例验证，不自动执行实际业务数据库任务 |
| 人员档案 | 在稳定主档 ID 上增加身份独立核验、吸毒相关记录、行政/刑事案件关系、分期戒毒措施及执行事件、检测随访、待办和责任交接；同一人可出现在不同业务视图，旧草稿/候选不自动确认或合并 |
| 重点场所 | 公寓、酒吧、娱乐场所、街区等台账，管理依据、责任岗位与复核日期，巡查整改、具体事件来源及资料引用、独立核验、处置反馈/复核办结及显式转录线索草稿 |
| 业务地图 | 按组织和原模块权限展示重点场所、场所事件、污水采样点；支持筛选/范围查询、地图选点、未定位补录、误标清除、坐标版本历史和相邻点位聚合。已定位结果最多显示 500 个并明确提示截断，列表分页保留未定位记录 |
| 界面与导航 | 顶部页名右侧显示功能说明，移除平台名称后缀；“智能解析”统一为“智能研判”，不再单设“模型服务”菜单；空列表不显示分页。新增表单沿用共享弹窗，失败保留输入、提交锁定及焦点恢复 |
| 证物模块移除 | 删除页面、状态、API、模型、分样/重量、保管交接、盘点调查及专用测试/恢复核对逻辑；保留旧迁移链以便升级，由 `0026` 删除八张证物表及旧角色授权 |

模块使用说明：[大屏与 AI](数据大屏与AI模型接入.md)、[线索闭环](情报线索闭环.md)、[分析建模](建模模型与技战法.md)、[人员档案](人员档案与戒毒业务.md)、[重点场所与业务地图](重点场所与业务地图.md)、[权限](系统管理与权限.md)。

## 最终菜单顺序

菜单按有效权限显示，无可见入口的组自动隐藏；旧页面缓存继续映射到更名或合并后的入口。

| 分组 | 顺序 |
| --- | --- |
| 综合总览 | 工作台 → 数据大屏 → 业务地图 |
| 业务办理 | 接警信息 → 情报线索 → 案件管理 → 人员档案 → 重点场所 → 污水监测 |
| 分析研判 | 智能研判 → 分析建模 |
| 管理审计 | 组织管理 → 用户管理 → 角色管理 → 权限管理 → 操作记录 → 系统日志 |

## 数据、权限与配置变化

人员身份和业务分别核验，记录来源、文书依据及历次更正；预计到期、待办完成、关联案件、单次检测或 AI 输出均不自动认定身份或解除措施。责任交接须接收确认，只转当前措施/未完成待办的办理责任，不扩大原单位全部案件或检测历史的可见范围。

新普通角色仍由管理员按岗位授予能力。升级旧兼容业务角色时，`0022` 补入大屏/AI 查询，`0024` 补入线索导入/下发/处置/复核，`0025` 补入建模/模型/技战法六项读写能力；不自动授予模型生成、系统管理、人员敏感资料、重点场所或地图权限。已有自定义角色不自动扩权，`0026` 仅清理其证物权限。新增敏感能力、原模块读写和对象范围在服务端分别校验，关键写操作与管理变更共享互斥、幂等/版本及同事务审计保护；新历史表加入 PostgreSQL 只追加权限清单。

页面 Key 默认在 `backend/.secrets/`，可通过 `WELLSPRING_AI_SECRET_DIR` 指定。离线容器用 `wellspring_ai_secrets` 卷持久化；数据库和密钥文件/卷须配套备份，单独恢复数据库不能恢复 Key。模型请求有主机允许名单、禁止重定向、输入/响应/耗时预算、并发限制及执行前/结果保存前权限复核。模拟模型仅验证协议和流程，不代表真实服务质量或兼容验收。

地图使用 WGS84 经纬度及本地授权 EPSG:3857 / XYZ / 256×256 PNG 底图，配置 `WELLSPRING_MAP_TILE_DIR`、`WELLSPRING_MAP_ATTRIBUTION`；Compose 对应只读 `wellspring_map_tiles` 卷及 `MAP_TILE_DIR`。当前没有真实底图时显示明确标注的坐标视图，不请求公网底图或地理编码；底图文件独立保管，数据库备份包含定位和历史。地图不保存人员位置、抓拍、人脸模板、轨迹或同行监控名单。

运行依赖锁增加 HTTP 客户端，前端增加固定版本 Leaflet/类型定义并按页面加载；保留完整 Python SHA-256 锁和 npm 锁文件。

## 数据库迁移及升级

| 迁移 | 变化 | 本地普通启动 |
| --- | --- | --- |
| `0022` | 模型服务、个人 AI 任务及大屏/AI 权限 | 受控备份后允许 |
| `0023` | 服务端 API Key 随机引用列 | 受控备份后允许 |
| `0024` | 组织类型、线索导入/分发/反馈历史和独立操作权限 | 受控备份后允许 |
| `0025` | 建模/模型/技战法资料及历史 | 受控备份后允许 |
| `0026` | **删除八张证物表及其中数据、清理角色证物权限** | **拒绝自动执行，须显式迁移** |
| `0027` | 人员主档扩展、业务/事件/待办/交接 | 受控备份后允许 |
| `0028` | 场所/巡查/事件/历史、定位及定位历史 | 受控备份后允许 |

1. 停止旧服务，核对数据库目标，备份代码、数据库、配置与密钥目录/卷；确认需要保留的旧证物资料已按既有要求妥善保存，并先在隔离副本验证升级。
2. 安装锁定依赖：开发环境 `python -m pip install --require-hashes -r backend/requirements-dev.lock`；前端进入 `frontend` 运行 `npm ci`。部署构建使用运行锁，不把本机 `.env` 或密钥放进构建输入。
3. 在项目根运行 `python migrate.py`，核对脱敏目标并显式升级到 `0028`。`0.0.5` 的 `0021` 升级路径包含 `0026`，普通启动将拒绝自动删除；手动入口先备份再升级。**`0026` 删除 `custody_events`、`custody_handovers`、`evidence_custody`、`inventory_investigation_events`、`inventory_investigations`、`evidence_inventory_observations`、`weight_events`、`evidence`，不能靠降级恢复。**
4. 离线环境先重新构建、核验 `wellspring/app:0.0.6`，再通过独立 `migrate` 任务升级并应用运行角色权限。修改默认标签不会升级既有容器或历史镜像。
5. 重启，检查 `/api/ready`、登录、授权菜单、核心办理及审计；为岗位配置新权限和组织类型，按需配置模型/密钥及底图。旧草稿保持待核验，旧点位不补造坐标。

历史迁移 `0017` 的精确重量函数已封装于历史迁移，当前运行层移除证物依赖；旧库仍能沿完整链升级。回退应恢复迁移前的匹配数据库、代码、配置及凭据备份，不覆盖或拼接不匹配结构。

## 版本与源码制品

前端包/锁文件、后端 API/OpenAPI、Compose 默认应用标签及两份部署环境示例统一为 `0.0.6`。本地 Git 提交及 `v0.0.6` 标签记录当前源码，未配置远程仓库，不表述为已推送。

`python scripts/build_source_release.py` 生成 `releases/wellspring-0.0.6-source.zip` 及 `.zip.sha256`。允许列表包含源码、文档、迁移、锁文件和测试，排除 `.git`、实际数据库、`.env`、密钥、运行日志、虚拟环境、依赖目录、构建和验证输出；归档与摘要需核对，不覆盖旧版本制品。该源码包不含可直接生产部署的镜像、模型 Key 或离线底图。

正式字段/专案共享矩阵、RLS、统一认证、独立受保护审计、正式保留期限及目标环境验收仍待完成。进程级登录限流不能覆盖多实例共享限流。ExcelJS 按需包体积提示及测试客户端弃用提示保留，均不等于验收失败或生产安全结论。
