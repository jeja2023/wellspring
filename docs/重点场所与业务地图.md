# 重点场所与业务地图

完整版本范围、发布验证与升级方式见 [0.0.7 版本说明](0.0.7-版本说明.md)。

本功能归入 `0.0.6` 开发验证版，迁移 head 为 `0028`。新增“重点场所”和“业务地图”两个入口，场所、巡查、具体事件与定位资料分开保存。地图首批覆盖重点场所、场所事件和污水采样点，不保存人员位置、抓拍、人脸模板、人员轨迹或同行监控名单。

## 场所台账与办理

场所可登记为公寓、酒吧、娱乐场所、街区或其他，填写本组织唯一编号、名称、区域、地址、责任岗位或承办人、纳入管理的依据和用途、下次管理复核日期。逾期仅提示人工复核，不自动调整状态或认定风险。资料可更正、启用或停用，保留历次快照及办理意见；停用后历史仍可查询，不再登记新的巡查或事件。

- **巡查整改**：记录巡查日期与事实；需要整改时填写期限。整改结果通过单独的复查操作登记，逾期显示提示，历史不被覆盖。
- **事件处置**：记录具体发生时间、信息来源、事实和资料引用。保存为待核验，另一名有权限人员核验确认或退回；补充资料后再次送核。核验确认后办理处置，提交反馈后由另一名有权限人员复核办结，也可退回继续办理。重新办理已办结事件须填写原因并留痕。
- **转录线索**：核验后的事件可显式新建一次待核验线索，需同时拥有场所办理、线索查询和线索写入权限。新线索仍为待核验记录，之后在现有情报线索模块按原有流程办理；不会因场所事件已核验而直接认定线索已核验或已办结。
- **资料边界**：当前保存文本引用、文书或报告编号，不提供图片/视频附件上传、自动 OCR、设备视频接入或外部系统真实性认证。资料引用以文本显示，不自动打开外部链接。

## 统一地图与业务入口

地图提供获准图层切换、名称/编号/地址筛选、已定位/未定位筛选、结果分页、平移缩放、相邻点位聚合、地图点选定位、坐标来源及历史。点击聚合数字可展开其中的点位。“点位列表”用于选择业务资料、查看详情及补录未定位记录，默认收起；点击工具栏按钮或地图点位后，从地图右侧滑出覆盖式抽屉，地图宽度和视野不因开合改变。地图容器按窗口剩余高度自适应填满可用空间，地图页不产生整页垂直滚动条；抽屉开合时焦点不触发外层滚动。抽屉内可独立滚动，地图仍可拖动或选点；支持关闭按钮、Escape 和关闭后焦点恢复，编辑/提交期间不能关闭以免丢失输入。移除内容区重复的“业务空间分布”标题卡，底图状态移到图例中。

地图查询结果分为两部分：地图最多显示 **500 个**已定位点，超出会明确提示筛选或缩小范围，不将部分点数表示成全部；展开的点位列表每页 20 条记录。点击“查询当前范围”才使用当前视野筛选，两部分使用同一筛选范围；“显示全部结果”取消范围限制。地址筛选只匹配现有文本，不向外部地理编码服务发送地址。

从场所详情、事件行或污水采样点行点击“地图定位”，可打开指定记录并补录坐标。从地图点击“查看业务”，场所及事件返回所属场所详情，污水点位返回污水监测模块。事件位置独立登记，不直接复制场所坐标或推断精确发生位置；未定位记录不画到地图上，也不使用 `(0,0)` 作为默认位置。

每次坐标修改保存来源、更正说明和历史版本，使用幂等键及版本冲突保护；清除误标时将经纬度一起清空并填写说明。清除坐标不删除业务记录或历史。未知类型、无权业务、其他组织记录以及人员类型不能通过定位接口新增点位。

## 坐标和离线底图

当前坐标输入使用 **WGS84 经纬度**，保留至小数点后六位；经度范围 `[-180,180]`、纬度范围 `[-85,85]`，界面按“经度 / 纬度”显示。经纬度必须成对输入或清空，拒绝非有限数和其他坐标系声明。六位小数是存储精度，不代表定位准确度。

底图支持经授权、坐标匹配的 **Web Mercator / XYZ / 256×256 PNG** 离线瓦片。`0.0.6` 原始版本只支持 WGS84；`0.0.7` 适配新增显式 GCJ-02 高德底图选项，业务坐标仍统一保存 WGS84。与 [Leaflet 1.9.4 官方参考](https://leafletjs.com/reference-1.9.4.html) 的默认投影一致；浏览器库已通过锁文件安装并本地构建，不依赖 CDN。

目录支持下列两种结构，路径均为瓦片自身的层级、列和行；无需搬动或批量重命名现有瓦片：

```text
map-tiles/
  12/
    3372/
      1551.png

# 或高德离线导出常见的嵌套结构
map-tiles/
  4/
    13/
      6/
        tile.png
```

本地开发在根目录 `.env` 配置后重启：

```dotenv
WELLSPRING_MAP_TILE_DIR=E:/maps/authorized-xyz
WELLSPRING_MAP_ATTRIBUTION=填写底图提供方要求展示的署名及说明
WELLSPRING_MAP_TILE_CRS=WGS84
WELLSPRING_MAP_MIN_ZOOM=0
WELLSPRING_MAP_MAX_ZOOM=20
WELLSPRING_MAP_CENTER=120.297066,31.576634
WELLSPRING_MAP_INITIAL_ZOOM=13
```

没有配置目录时显示明确标注的经纬度网格“坐标视图”，不伪造道路与地名，也不请求公网底图。已配置但缺少当前位置瓦片时仍显示网格；业务点位与坐标维护继续可用。底图不随源码或镜像分发，文件由部署方独立提供和保管。当前已在本机对用户提供的原生高德嵌套 PNG 瓦片做读取与浏览器叠加验证；这不等于完整覆盖、定位精度或底图授权验收。

原生高德瓦片设置 `WELLSPRING_MAP_TILE_CRS=GCJ02`；该选项只声明底图坐标，不改变数据库坐标系。高德使用 GCJ-02，参见[高德官方坐标说明](https://developer.amap.com/api/javascript-api-v2/guide/abc/basetype)。前端使用固定版本、MIT 许可的 [coordtransform](https://github.com/wandergis/coordtransform) 做离线近似换算：WGS84 业务点转换后叠加到高德底图，地图点击转换回 WGS84 后填入表单，主界面不常驻技术说明，坐标编辑抽屉仅提示选点/输入方式及保存前核对位置；近似换算的说明保留在本文。范围查询将视野边界换算回 WGS84 并保留少量边缘余量，不承诺测绘精度，也不以往返计算误差代替实际地面精度。

例如已有 `E:/wellspring-data/MapTiles/4/13/6/tile.png`，根目录填 `E:/wellspring-data/MapTiles`，不能填到 `4/13/6`。确认原始高德坐标后配置 `GCJ02`，按现有瓦片设置最大级别（如 `16`），初始中心为**底图原生经度,纬度**，初始级别须在配置的最小/最大范围内。本机默认采用高德城市数据的无锡市中心点（GCJ-02：`120.301663,31.574729`），默认 13 级；WGS84 底图对应近似值为 `120.297066,31.576634`。首次进入不自动缩放到全部业务点，地图右上角持续显示当前级别；手动“适配点位”和从业务记录定位仍可改变视野。高德坐标不应直接粘贴进 WGS84 手工输入框；可使用地图选点自动换算后核对保存。

BD-09、投影平面坐标、TMS 反向行号或 EPSG:4326 瓦片仍不支持直接套入，不猜测或静默更改坐标系。当前不做地址定位、空间面积/距离统计或任意内网地图 URL 代理。地图比例尺仅辅助查看。

瓦片由后端读取本地目录，路径限定在配置目录内，层级最大 20、单文件最大 2 MB，使用当前会话认证和私有、不缓存的响应；令牌不放入瓦片 URL。底图缺失不会尝试从网络补充。文件与目录应由管理员管理，应用只需读取权限。

Docker Compose 增加只读挂载的 `wellspring_map_tiles` 卷，应用内目录为 `/app/map-tiles`。默认 `MAP_TILE_DIR` 为空，仍使用坐标视图；运维人员按既有数据导入规程将底图写入该卷后，设置 `MAP_TILE_DIR=/app/map-tiles` 和 `MAP_ATTRIBUTION`；需要时配置 `MAP_TILE_CRS=GCJ02`、`MAP_MIN_ZOOM`、`MAP_MAX_ZOOM`、`MAP_CENTER`、`MAP_INITIAL_ZOOM`，重建应用容器加载配置。也可通过本地 Compose 覆盖文件将获准目录只读绑定到该路径。底图不写入应用镜像或数据库；数据库备份不包含底图文件，底图需独立保管，坐标和历史包含在数据库备份中。

## 组织与权限

| 权限 | 能力 |
| --- | --- |
| `places.read` | 本组织场所、巡查、事件与历史查询 |
| `places.write` | 建立/更正/启停场所、登记巡查和事件、复查整改、处置反馈 |
| `places.review` | 独立核验事件、退回、复核办结及重新办理；仍需 `places.read` |
| `geography.read` | 进入地图并查询获准业务图层；仍需该图层原模块的查询权限 |
| `geography.write` | 维护地图坐标；仍需 `geography.read` 和对应模块的查询/写入权限 |

这五项新权限不自动授予普通兼容角色或已有自定义角色；由超级管理员按岗位配置。地图不是额外的数据授权入口：其他组织的场所、事件、采样点及其坐标/历史/数量均不可见，管理员也遵守当前组织数据范围；组织层级不会自动共享所有地图资料。地图事件摘要只返回标题、状态和定位信息，不返回事实原文、资料引用或处置内容。

场所/坐标写入与账号、角色、组织变更共享管理锁，办理时重新核对权限和会话；业务、历史和审计在同一事务提交。新历史表列入 PostgreSQL 只追加授权清单。返回地图、场所或退出登录时，旧会话请求不得将资料写入新会话。

## 升级和验证

先停止旧程序并备份，使用根目录 `python migrate.py` 升级到 `0028`。`0028` 只增加六张新表，不给旧人员或场所补造坐标；已有 `0027` 时可由受控本地启动流程执行此增量。如果更早版本还需执行 `0026` 删除迁移，仍须按既有明确备份与显式迁移要求处理。回退应恢复匹配备份。

测试使用隔离数据库、合成场所与事件、合成坐标及瓦片；未访问用户现有数据库。覆盖跨组织及模块权限、独立核验与处置、转线索幂等、整改审计失败回滚、坐标冲突/清除/历史、500 点上限、认证瓦片读取、浏览器地图选点及窄屏布局。最终实际检查结果记录于[更新日志](../更新日志.md)。
