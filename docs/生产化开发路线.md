# 清源生产化开发路线（待确认）

## 目标与当前状态

目标是在明确业务规则和目标环境后，形成可离线部署、可运维、可验收的正式版本。现有代码是开发验证基线，尚不能接入真实业务数据，也不能承诺已达到生产上线要求。

“接警信息”维护原接警Excel台账，“案件管理”维护案件草稿及下游关联。两者通过明确的新建/关联和保留原文快照的来源关系衔接，不自动匹配历史编号或认定立案。当前实现仍只允许虚构数据验证：组织过滤和基础审计不能替代正式权限、独立审计和生产安全验收。正式转办审批、跨组织转交及接警拆分为多案的规则仍需确认。

## 当前试点方向

- 首先面向单台 Windows 电脑试运行；前端与后端共用一个 Docker 应用容器，PostgreSQL 使用独立容器，CPU、Windows 版本及目标容器环境仍需确认。
- 预计约 1–10 人试点；是否多人同时通过网络访问及并发目标仍需确认。
- PostgreSQL 17 专用数据库和本地账号作为当前规划方向；Docker Desktop 的兼容性、离线镜像、数据库运行环境与账号安全规则仍需验证和确认。
- 案件信息先以服务端持久化为优先切片；正式权限、导入导出、审计和目标环境验收仍须完成，不能据此认定试点可使用真实数据。
- 用户已确认沿用页面的案件信息字段，删除“摘要”“详情”字段，将“涉案物”命名为“涉案物品”，并包含备注；接警编号必填，其余字段可为空。日期含义和格式仍待确认。
- 接警编号在全系统内唯一；删除后记录从普通列表隐藏且保留，已删除编号仍保留。已增加超级管理员对已隐藏记录的查询和恢复，以及案件信息跨组织访问；正式角色矩阵、完整审计追溯和目标环境验收仍未完成。

## 先确认的事项

- 目标操作系统版本、CPU 架构、单机或内网多用户、是否允许容器，以及离线安装方式。
- 预期用户数、并发、数据规模、可用性要求、备份频率和允许的数据恢复范围。
- 目标数据库及供应商支持；目前 PostgreSQL 是候选目标，SQLite 仅作为开发用途，国产数据库兼容性尚未验证。
- 本地账号还是统一身份认证；组织、角色、数据范围、字段查看及导入导出权限的责任人和规则。
- 接警编号的唯一范围与归一化规则；Excel 时间、电话、空值和错误数据的处理规则。
- 删除是撤销、软删除、更正还是保留历史；谁可以操作、是否需要复核及保留期限。不能自行把测试页的删除当成正式规则。
- 首期是否只包含案件信息，或同时包含线索、人员、证物和其他业务；每项由业务负责人确认验收标准。

## 实施顺序和验收依据

1. **业务与权限基线**：明确字段字典、唯一范围、角色和组织／专案数据范围、记录更正及导入导出权限。产出可核对的业务案例和权限反向案例，未确定的规则保持待确认。
2. **持久化案件信息**：使用数据库迁移建立数据模型、约束和版本字段；实现服务端分页、筛选、统计、读取和受控变更，前端改为调用接口。验证重复编号、事务、并发冲突、不同组织隔离及错误恢复。字段为空的规则以业务确认结果为准。
3. **身份、权限和审计**：按批准矩阵在服务端校验操作与数据范围，完善账号生命周期、撤权、会话安全、登录防护和关键操作审计。审计需覆盖成功与拒绝，避免敏感原文进入普通日志；按目标数据库单独验证隔离策略。
4. **正式导入导出**：从测试用浏览器内处理迁移到有授权控制的正式流程，明确文件大小与解析限制、逐行校验、预览确认、重复处理、事务、幂等、失败回报及审计；验证 Excel 公式、异常文件和导出安全。实际数据不得在规则及环境验证前导入。
5. **业务闭环**：按首期范围逐项补齐案件与相关业务流程、关系、复核、错误处理和对应权限，不将页面或演示数据视作完成业务交付。
6. **交付及运维**：固定目标架构与依赖，制作和校验离线制品；配置受控密钥、传输保护、数据库备份、监控、故障处理及升级流程。在目标环境演练安装、升级、备份和恢复，并验证数据完整性。
7. **上线验收**：完成业务、权限、并发、性能、安全、恢复及国产化目标环境测试；保留证据、已知问题、运维交接和相关责任人的验收结论。只有通过约定验收后才能决定是否上线。
