# 工作台与数据大屏

工作台负责日常办理，数据大屏负责组织业务统计。两页保留独立入口，工作台移除案件总数和模型总数、入门说明卡，避免同一统计重复展示。大屏继续提供业务总量、7/30/90 天新增趋势、状态分布、全屏和 AI 统计解读。

## 工作台

- 四类事项：待办理、待复核、已逾期、今日到期。卡片数字由服务端统计全部匹配事项，不以当前分页数量代替。逾期严格按北京时间自然日判断，今天到期不算逾期。
- 模块筛选、10 条分页、手动刷新和失败重试。加载失败保留最后成功的列表/队列/筛选；旧请求与卸载后的响应不会覆盖新状态。页面不再常驻显示排序/时区说明及底部更新时间/共享事项提示。
- 办理事项表将事项名称、事项类型和业务模块独立分列，表头与数据保持单行，较长内容在表格内横向滚动查看。
- 工作台按窗口剩余高度铺满，整页不纵向滚动；较长列表在表格区域内滚动，表头保持可见，筛选和分页固定在表格外。较矮窗口收紧顶部卡片和说明，其他业务页面沿用各自布局。
- 列表区分“我承办”“本单位可办理”“本单位待接收”。共享事项不冒充个人指派，不改变现有独立复核规则。
- “查看办理”进入线索工单详情、层级流转、人员具体分区/记录、场所巡查/事件，或按报告定位污水结果；工作台只查询，不自动提交办理动作。人员、场所和交接列表的工作台定位条件始终叠加原对象授权，可清除定位查看本分区全部记录。
- 工作台仅保留事项处理与提醒，移除底部“快捷办理”区域，新建业务从各业务页面的原入口办理。有大屏权限时提供“查看业务统计”。登录/恢复会话不再预加载案件列表，目标页面自行加载所需资料。

## 事项范围与权限

| 来源 | 待办理 | 待复核 |
| --- | --- | --- |
| 本组织核查工单 | 本人承办、待办理或退回 | 本组织待复核、提交人明确且不是本人 |
| 层级线索 | 接收单位未指定承办人的待接收、本人的处置中/退回事项 | 下发单位的待复核反馈，承办人明确且不是本人 |
| 人员资料 | 当前单位开放待办、本人待补充的退回业务 | 其他人录入的待核身份/业务，以及发给本单位的责任交接 |
| 重点场所 | 未完成整改、可维护的事件处置/补充资料 | 其他人录入的待核事件、其他人提交的待办结反馈 |
| 污水检测 | 本人录入且被退回的检测结果 | 其他人录入的待复核结果 |

每个来源需同时具有原模块的查询与对应办理权限，人员资料另遵循身份/健康/业务类型/责任单位限制。只读账号仍可进入工作台，返回空事项和明确提示，不新增权限代码或自动授权。不显示无期限事项为逾期，不把预计结束日期当作措施自动解除依据，不统计已完成、未知提交人或本人不能独立复核的事项。

## 接口与兼容

新增 `GET /api/workbench/tasks`，参数 `queue=todo|review|overdue|due_today`、`module=all|intelligence|persons|places|wastewater`、`page` 和 `page_size`（默认10，最多50）。返回列表、四类计数、可办理模块、北京时间日期和更新时间。数据库 head 保持 `0028`，没有新增 DDL；现有工单接口继续兼容。

新增审计代码 `WORKBENCH_VIEW`（“查看工作台办理事项”），日志不记录列表标题或查询原文。日期、分页、独立复核、跨组织及角色变更、只读空态、失败/乱序和会话清理纳入回归验证。

本次验证：9 项相关后端回归、51 项前端测试、23 条完整浏览器流程和类型检查/生产构建通过。本机 PostgreSQL 页面另完成 12 项桌面/窄屏、具体事项定位及快捷表单检查，独立只读账号空态检查通过。现有开发服务已加载新接口，数据库仍为 `0028`；未修改既有业务记录和模型服务配置。
