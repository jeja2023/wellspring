# 人员档案、涉案关系与戒毒业务

完整版本范围、发布验证与升级方式见 [0.0.7 版本说明](0.0.7-版本说明.md)。

`0.0.6` 新增迁移 `0027`，在原人员档案的稳定 ID 上扩展主档及业务记录。旧姓名、来源、候选案件及未核验状态原样保留；迁移不把旧待核验档案认定为吸毒人员、刑事案件人员或已执行某项戒毒措施。

## 一人一档，业务分别记录

人员主档保存姓名、来源、证件/身份依据、联系方式、身份核验及当前责任单位/责任人。相同姓名可保留多份待核对档案；同一授权范围出现同类型同证件时提示核对，不自动合并或覆盖，不根据姓名、检测结果或 AI 输出作身份认定。

| 维度 | 保存内容 | 与主档的关系 |
| --- | --- | --- |
| 吸毒相关记录 | 待核实报告、检测事实、吸毒事实依据或成瘾认定依据；相关物质、内容、来源和文书 | 每次独立登记和核验，不用一项永久人员标签代替历史 |
| 正式案件关系 | 本单位可查询案件、行政/刑事/其他性质、在案角色、阶段、涉嫌事项、处理结论和依据 | 一人可关联多案；同一案件角色变化通过更正记录留痕 |
| 戒毒措施 | 自愿戒毒、社区戒毒、强制隔离戒毒、社区康复；决定日期、机关/医疗机构、实际执行机构和预计结束日期 | 每次独立措施，不预设所有人员必须依次经历各措施 |
| 执行事件 | 实际报到、入所/开始治疗、解除/结束、变更、撤销；实际日期、文书和意见 | 与措施绑定，预计日期或待办完成不自动改变执行状态 |
| 检测与随访 | 初筛、实验室/复核检测及结果；随访、帮扶、后续人工指定日期 | 记录来源和核验状态，不自动据阳性结果生成吸毒认定 |
| 责任交接 | 发起单位、接收单位、原因、确认/退回、当前措施与待办的责任变更 | 共用稳定人员 ID，不自动共享原单位全部业务历史 |

社区戒毒、强制隔离戒毒和社区康复的法律依据及主体不同，应分别登记；社区戒毒执行机构可填写乡镇、街道等主体，不限定为警务组织树节点。参见[《禁毒法》第三十三、三十四、三十八及四十八条](https://www.beijing.gov.cn/zhengce/zhengcefagui/qtwj/201104/t20110427_780651.html)。

刑事案件分别记录犯罪嫌疑人、被告人和有文书依据的生效裁判结论，不能因关联案件确定有罪；“生效裁判结论”要求人工填写裁判文书和生效日期，系统只校验资料完整性，不代替司法认定。参见[《刑事诉讼法》第十二条](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/bgt/art/2025/art_48b3b0c3f954448e996602a71fc6f878.html)。

## 页面视图和操作

人员档案主入口提供“全部人员”“涉案人员”“吸毒人员”“戒毒人员”“待核人员”和获准人员的“管辖交接”。这些是有交集的业务筛选，不是互斥人员类型，不能把各视图数量相加当作总人数。

- 涉案人员：当前组织可查询案件中，有已核验正式关系的人员。旧候选关联不会自动转正式。
- 吸毒人员：存在已核验的“吸毒事实依据”或“成瘾认定依据”记录；一般报告或检测事实不会自动进入此视图。
- 戒毒人员：存在已核验且待执行/执行中的措施；不包括已经结束或撤销的措施。
- 待核人员：主档身份尚未核验或已退回。业务记录核验状态另行保存。

列表分列展示名称、脱敏证件、身份核验、正式案件关系数、当前措施、责任单位和待办。进入“查看档案”，在基础信息、吸毒记录、案件关联、戒毒措施、检测记录、随访帮扶、待办事项、历史候选和历史记录中分别办理；无权限分区不显示，不能从无权限接口取得内容或隐藏记录总数。

### 身份和业务核验

1. 创建主档仍是未核验档案，可稍后维护证件或其他身份依据编号和责任人。
2. 另一名具有身份查询/核验权限的人员核对依据后确认、退回或撤销核验。创建/最后修改人不能核验本人资料，确认前必须有身份依据编号。
3. 正式案件关系和戒毒措施要求主档身份已核验。每次登记填写事实/决定日期、来源、文书/报告编号及登记依据，保存为待核验业务记录。
4. 另一名有该类维护及核验权限的人员确认或退回；退回/待核记录可补充修改，重新提交后仍需独立核验。
5. 已核验的非措施记录通过“更正记录”创建新版本，核验新记录后旧记录变为已被更正；核验前旧记录继续有效。措施的变化通过执行事件处理，不以新记录覆盖其执行历史。

核验是业务人员对来源和依据的记录，不连接外部权威身份、法院、检测或戒毒系统进行真实性认证。当前只保存文书/报告引用、文本依据和历次记录，不包含附件上传、OCR 或权威文书电子签名校验。

### 措施分期和提醒

决定日期、实际开始、预计结束、实际结束分别保存。社区戒毒/社区康复登记实际报到，自愿戒毒/强制隔离戒毒登记入所或开始治疗。执行动作与措施类型和当前状态不符、实际日期早于决定/开始日期或晚于今天时拒绝。

措施核验后，可依据人工填写的报到核对日期和预计结束日期创建核对待办；已核验检测/随访记录中的人工后续日期可生成后续待办。也可手工添加检测、随访或期限核对任务。没有硬编码法律期限、检测频次、15/7/3 天提醒或风险评分。

**到期仅显示“到期待核对”或逾期待办。** 完成待办只记录核对结果；必须另行依据文书和实际事件登记解除、结束、变更或撤销，才改变措施状态。变更不会自动产生下一项措施，也不根据是否服刑、涉案或单次检测自动转换状态。多个待执行/执行措施并存会提示核对，不自动选优先级或结束其中一项。

### 管辖责任交接

当前责任单位对已核验身份发起移交，由目标启用单位确认或退回，发起单位可撤销未处理申请。同一人员同时只允许一项待接收申请；接收前目标只能查看姓名、脱敏证件和移交原因，不能读取整份档案。

接收后，主档责任转到目标单位，当前已核验的待执行/执行措施及未完成待办转移办理责任。原单位的案件关系、吸毒记录、检测和随访历史不会全部自动转移；接收单位仍需相应身份/敏感业务权限，案件还需本单位案件查询范围。原单位保留自身历史记录，但不能继续修改现由其他单位负责的主档或措施；旧候选关联改为历史查看。

目标单位已有相同证件档案时阻止直接接收并提示人工核对，不自动合并。当前没有人员主档合并、批量跨区同步、撤销已完成交接或权威跨部门数据交换。涉及人员责任或待接收移交的单位不能直接停用，避免形成无人负责的档案。

## 权限与敏感资料

| 权限 | 用途 |
| --- | --- |
| `persons.read/write` | 主档基础查询/维护，原有人员接口兼容 |
| `persons.identity` | 完整证件、出生日期、联系方式及身份核验所需资料 |
| `persons.health` | 吸毒相关、戒毒措施、检测/随访详情及相关视图/待办 |
| `persons.verify` | 主档身份和业务记录的独立核验；还需相应身份/业务权限 |
| `persons.use` | 登记、补充和更正吸毒相关记录 |
| `persons.cases` | 维护正式案件关系，另需 `cases.read` |
| `persons.treatment` | 登记戒毒措施及实际执行、变更、解除等事件 |
| `persons.followup` | 检测、随访、人工待办和处理结果 |
| `persons.transfer` | 发起、接收、退回或撤销待处理责任移交 |

新增敏感权限不自动授予旧“业务用户”兼容角色或自定义角色；超级管理员可配置指定岗位。非案件敏感记录的办理须同时有 `persons.health`，未授权时接口不返回原文、检测详情或敏感统计数量。没有完整身份权限时仅返回脱敏证件，不返回联系电话、地址或完整证件。

主档可见不会扩大所有案件和历史资料范围；下属组织不会自动继承上级所有人员资料。组织/账号/角色变更与办理写操作使用共享互斥、版本条件和幂等保护，业务、历史、待办变化和审计同事务提交。日志不打印业务原文、证件或 SQL 参数。

身份及健康资料属于敏感信息，应按岗位、用途和实际环境保护，参见[国家网信办个人信息保护政策法规问答](https://www.cac.gov.cn/2026-01/09/c_1769688003183197.htm)。本地开发仅使用合成数据；本轮没有宣称数据库字段已加密、建立正式保存期限、配置生产访问审计平台或满足生产认证要求。持久化文本需受数据库、磁盘、备份和部署环境保护。数据不会从人员页面自动发送给 AI 或自动作为个人风险评分输入。

## 数据升级和验证

先停止旧程序并备份，使用根目录 `python migrate.py` 升级到 `0027`；已有 `0026` 时该增量可由受控启动流程执行，若更早还待执行 `0026` 删除迁移，仍须显式命令和核对备份。新增四张人员业务/事件/待办/移交表及主档字段，不自动确认身份、不生成措施、不把旧候选关系变成正式关系。

验证使用隔离 SQLite、合成人员与文书编号：主档身份独立复核、同名不合并、证件防重/脱敏、刑事角色与吸毒记录交叉、措施分期/实际执行、待办不自动解除、退回补充与更正历史、责任交接的最小授权和幂等、审计失败完整回滚。迁移覆盖全新库与 `0026 → 0027`、旧待核验档案保留和模型一致性；用户现有数据库未执行迁移。实际测试结果在检查结束后记录于更新日志。
