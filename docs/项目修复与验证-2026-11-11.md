其他优化包括统一带时区 UTC 输出、幂等重放重新授权、拒绝异常复核状态、翻页跳过四次重复统计/选项查询、组织列表/审计/会话/任务索引、过期会话清理、进程级登录节流、请求体大小/读取超时、数据库连接与查询等待上限。列表使用明确标记的十三列摘要预览，完整详情由独立接口加载，避免把截断内容提交回数据库。新增请求耗时及编号诊断，关闭默认含查询词的访问日志，并隐藏 SQL 异常中的绑定参数。

Excel 解析移到可终止 Worker，执行前核验 ZIP 元数据与实际解压流大小，再限制行列、单元格和总字符；支持取消与超时，不再依赖仅安全上下文可用的 randomUUID。ExcelJS 仍按需加载。导出也限制 1000 条及 200 万字符，超出时要求缩小筛选。

交付工具使用构建输入允许列表，记录源码摘要、提交/工作区状态、平台和依赖锁摘要；已删除不匹配的旧部署入口。备份通过二进制流写入，恢复演练使用独立容器，不挂载已有数据库卷，输出数据计数、迁移版本和重量账一致性报告。

**升级方式**

1. 停止本项目进程，备份数据库和配置，并先在备份副本验证升级。
2. 后端安装 `backend/requirements-dev.lock`（生产构建使用 requirements.lock），使用 `--require-hashes`；前端运行 `npm ci`。
3. 在项目根目录运行 `python migrate.py`，核对其显示的脱敏目标，当前版本迁移到 `0021`（初次审查修复的目标为 `0018`）。
4. 重新启动项目并检查 `/api/ready`、登录、核心业务及审计。

`0017` 会把 SQLite 既有六位小数显示值转换成精确文本。历史浮点运算已经丢失的精度无法恢复；遇到超范围、非有限或负余额会在修改结构前停止，需检查原始记录。SQLite 精确重量迁移不提供会丢失精度的降级；回退应恢复经过验证的备份。PostgreSQL 的重量存储格式不变。
