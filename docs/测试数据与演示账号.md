# 测试数据与演示账号

本机开发环境可以显式导入一套关联完整的虚构数据。业务名称和主要说明带 `【演示】` 标识，编号使用 `DEMO-` 前缀；不包含真实身份号码、电话号码或业务事实。数据只由命令行工具导入，应用启动和数据库迁移不会自动填充。

在项目根目录运行：

```powershell
backend\.venv\Scripts\python.exe scripts/seed_demo_data.py --owner admin
backend\.venv\Scripts\python.exe scripts/seed_demo_data.py --owner admin --apply
```

第一条在事务中生成并回滚，用于预览数量；第二条备份本机开发库后正式写入。使用根目录 `.env` 的数据库配置或显式 `DATABASE_URL`，仅允许本机 PostgreSQL 和 SQLite，要求数据库已为 `0028`。`--owner` 必须是当前启用的超级管理员账号；工具不会修改其密码、权限、组织类型、层级或模型配置。

工作台“我的核查工单”和“待我复核”、案件导入记录、AI 历史均按账号过滤。导入后继续使用 `--owner` 指定的账号登录，可以查看本组织数据和该账号个人历史。演示业务员和核验员用于不同人办理；只读观察员用于检查查询权限。需要查看“收到的线索／我下发的线索”时，使用报告中的 `demo_branch_*` 账号；该账号所属演示大队具有合法的演示支队和派出所上下级，现有“系统运维”等组织不被擅自改为业务层级。

写入完成后，本地 `releases/demo-data/` 中生成私有 JSON 报告，包含实际插入数量、归属、备份位置以及六个新账号独立随机生成的密码。原有账号密码保持。报告和备份均被 Git 和源码包排除，不应分享或提交。PostgreSQL 备份为 `backend/backups/demo-data/*.dump`，SQLite 使用 `.sqlite3`，另有 SHA-256 元数据。

同组织已有完整导入标记时，重复执行直接退出，不重复生成或覆盖数据；缺少标记但存在冲突记录时整次回滚并报错，不修补或重置用户后来编辑的数据。异常导致整个业务写入回滚，备份仍保留。本工具不提供清库、覆盖导入或破坏性删除功能。

隔离回归检查实际页面 API、所有人员业务标签、趋势与大屏口径、记录可继续办理、跨组织/个人历史隔离，以及旧记录保全、事务回滚和重复运行。真实地图覆盖、实时 AI 生成仍取决于本机实际配置，不会用伪造联网结果替代。

2026-11-12 已向本机 `wellspring` PostgreSQL 开发库、`admin` 所在组织实际导入 1,265 条记录，覆盖 38 张表；备份文件摘要和归档目录核验通过，导入前已有记录摘要保持一致。6 项相关后端回归通过，实际运行界面完成 34 项页面/标签检查，无页面脚本错误；大屏六项总量为 28、24、9、24、18、84，地图显示 30 个合成业务点位。再次执行导入为无操作，数据库迁移仍为 `0028`。验证资料仅保存在本地 `releases/demo-data-validation/`，未纳入源码包。
