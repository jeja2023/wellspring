**接警信息与案件管理 · 使用与改造记录**

用户已确认采用“接警信息台账 → 明确转办/关联 → 案件管理”的方案。本次重命名及关联功能不改变历史记录的身份，不把接警事实自动认定为立案或并案。

| 入口 | 数据与用途 |
| --- | --- |
| 接警信息 | 原“案件管理”的接警 Excel 台账，包含接警编号、报警内容、处警结果等20个原字段；支持导入、查询、统计、编辑、隐藏及管理员恢复 |
| 案件管理 | 原“业务案件”的案件草稿，包含案件编号、名称、草稿状态；用于证物、线索、人员候选及案件关系 |
| 数据导入 | 现有 CSV 导入仍创建案件草稿；与接警 Excel 来源区分，不因编号相同自动建立关联 |

**办理流程**

1. 在“接警信息”中导入、核对记录，点击“转办 / 关联”。服务端再次获取完整原文和当前版本，避免将列表摘要当成原始数据。
2. 选择“创建新的案件草稿”，核对案件编号与名称并填写依据；或者选择“关联已有案件”，查询、分页并明确选择本组织案件。
3. 提交成功后保留原接警记录，建立来源关系并保存当时全部接警字段的快照、接警版本、办理人、时间及依据。新建案件仅写入填写的案件编号/名称；敏感接警字段不复制到普通案件列表。
4. 从接警列表“关联案件”或完成窗口“查看案件”跳转到案件管理。案件行“接警来源”可查看来源、快照与历史；证物、线索和人员候选继续关联同一个案件ID。
5. 关联错误时，在案件的接警来源中填写原因“撤销关联”。只结束该关联，不删除案件、接警记录或来源快照。重新核对后可再次关联；撤销记录仍可查询。

当前每条接警信息至多有一个有效关联案件；同一案件可以接受多条接警来源。需要一条接警拆成多案、跨组织转交或正式审批时，应另行确认规则与权限，不通过重复点击模拟。原有案件没有接警来源时仍正常使用；没有对历史编号执行匹配、补建关系或自动合并。

**一致性与权限**

- 幂等键、数据库部分唯一索引、来源版本条件更新及同事务审计共同防止重复建案。案件编号重复会提示核对后关联已有案件，不静默使用或覆盖已有记录。修改、隐藏、转办同时发生时，由版本冲突阻止使用过期原文。
- 转办、关联、撤销和案件来源读取均要求本组织范围。管理员跨组织查看接警信息的现有能力继续保留，但这种查看权限不会自动授予跨组织建案、案件读取或转办权限；只有授权可见的案件编号才出现在关联信息中。
- 原接警修改或隐藏不覆盖来源快照，案件及证物等下游数据不受自动修改。来源中标示原记录是否已隐藏；快照明确是关联当时的历史版本。
- 运行数据库角色仅获来源表 SELECT/INSERT 及撤销状态相关列的 UPDATE；原文快照、源/目标ID、办理依据等列不可通过该角色更新，表不授予 DELETE。业务与审计任一失败均回滚创建或关联操作。
- 撤销关联不会自动删除此前创建的草稿；如需案件草稿撤销/归档和历史保留，须按确认的业务规则另行实现。本轮没有引入正式案件法律状态。

**升级与兼容**

新增迁移 `0020`，仅增加来源关系表和索引，不更新历史业务行。已到 `0019` 的本地库可由 `python start.py` 备份后自动升级；旧于允许自动升级边界的库按提示运行 `python migrate.py`。离线部署运行独立 migrate 任务并应用表列权限。

导航缓存改用 v2 键，旧“案件管理”正确恢复为“接警信息”，旧“业务案件”恢复为新“案件管理”；重新登录和刷新不会误开另一类记录。现有 `/case-information`、`/cases` API路径及Excel字段保持兼容，导入模板、导出文件和页面显示统一称“接警信息”。

**验证**

验证包含新建/关联、重试幂等、重复编号、过期版本、隐藏记录、管理员跨组织查看限制、来源快照不被原文更正覆盖、撤销后再关联、同案件多来源、审计失败回滚和分页批量关联查询。PostgreSQL 验证同键/不同键并发转办只创建一个案件、源表列权限及真实迁移；浏览器覆盖导入接警、新建案件、第二条接警关联已有案件、查看快照、撤销，以及既有证物与污水流程。

实际结果：后端141项、前端37项全部通过；5条浏览器端到端通过；类型检查、生产构建及 `git diff --check` 通过。数据库验证使用隔离 PostgreSQL 18 与合成 SQLite，没有升级用户现有数据库。原有测试客户端有一项 httpx 弃用提示，按需加载的 ExcelJS 有构建体积提示，均未造成检查失败。

构建后的镜像再次通过全部5条浏览器流程及就绪、静态入口和安全响应头检查；最终隔离验证容器已自动移除。

容器冒烟工具使用独立临时内存盘存放合成 SQLite，默认冷启动上限180秒，超时保留容器日志；每个容器使用独立的浏览器测试输出目录，避免并行验证互相清理跟踪文件。上述设置仅用于隔离验证，不改变正式 PostgreSQL 持久化或业务配置。
