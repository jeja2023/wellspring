## 已实现的开发切片

- Vue 3 + TypeScript 工作界面，开发环境标识；本地命名账号、短期服务端会话及退出撤销。
- 用户、角色、权限和组织管理及服务端模块授权：本组织委派管理、密码重置/修改、会话撤销、版本冲突和最后超级管理员保护。用户的组织/角色、角色的代码/级别独立成列。
- 界面统一为全宽列表、共享弹窗、完整表格边框及连续序号、右对齐共享分页；页名只在顶部栏展示。权限管理使用相同的单卡片筛选/表格/底部操作布局，保留筛选、草稿保护及授权依赖校验。
- 业务导航中的“智能解析”位于“人员档案”之后、“操作记录”之前；系统管理分组在业务导航之后，菜单按有效权限展示。
- 当前组织内的案件草稿、服务端分页和筛选，以及案件关联／协办关系（不代表并案）；证物初始重量登记、分样、双向重量流水、盘点观测与调查说明复核，以及同组织单件保管交接验证（均不自动调整余额）。
- 人员最小草稿：仅保存名称、来源和未核验状态，可记录同组织案件的待核查候选关联；不进行身份核验或自动去重。
- 案件管理内“批量导入 / 导入记录”支持虚构案件 CSV 暂存、逐行核对及仅新增草稿的确认；不单设主菜单。“操作记录”提供本人审计记录查询；智能解析目前仅展示未接入状态。
- 接警信息使用独立台账，支持 Excel 导入、筛选、统计、编辑和保留记录的隐藏；接警编号全系统唯一，隐藏后仍不可复用。可明确新建案件草稿或关联已有案件，保留原记录、办理依据与历史快照；管理员的跨组织接警查看不会扩大案件办理权限。
- 开发验证用情报线索：草稿、组织内标题／来源与状态筛选、人工核验、核查工单、重分派、退回及独立复核，含处理事件与基础审计，并支持手动填写办理期限、工作台个人工单以及同组织案件关联／撤销。
- 组织范围由服务端账号决定，基础业务动作与本地审计同事务提交；分样采用数据库条件更新，防止余额不足。
- SQLAlchemy 数据模型与 Alembic 初始迁移，支持以 `DATABASE_URL` 指定 PostgreSQL；默认 SQLite 仅供开发。
- “案件管理”提供案件草稿、接警来源与案件关系，供证物、人员候选和线索关联。旧“案件管理”改称“接警信息”，旧“业务案件”改称“案件管理”；导入接警不自动建案，需明确办理，不表示正式立案。新增独立来源迁移 `0020`，已到 `0019` 的本地库可在启动时备份后升级。
- 查询具备会话隔离、取消与乱序保护；Excel 使用可取消 Worker 和解压预算；离线工具提供可信校验引导与隔离恢复演练。
- 污水监测支持点位与采样台账、检测结果修订与不同账号复核、同口径浓度趋势；不自动推算吸毒人数或个人结论。新增 `0019` 独立数据表，已到 `0018` 的本地库可在启动时备份后自动升级。

## 本机运行

需要 Python 3.12、Node.js 和 npm。仅使用虚构数据。

当前迁移 head 为 `0021`；增加角色授权及账号/组织管理，旧账号保留原有业务范围，普通账号不自动获得系统管理权限。停止旧服务后运行启动器，按受控迁移规则备份、升级；遇到未批准自动执行的历史迁移，检查后运行 `python migrate.py`。

### 使用本机 PostgreSQL 开发库

本机已安装并运行 PostgreSQL 时，可以在项目根目录使用 `backend\.venv\Scripts\python.exe setup_postgres.py` 交互式创建专用的 `wellspring` 数据库和 `wellspring` 数据库账号；脚本会要求输入 PostgreSQL 管理员密码、新数据库账号密码和应用 `admin` 密码。目标数据库或账号已存在时会停止，不覆盖。该步骤只用于新建开发库，不会导入 SQLite 数据；数据库角色拥有此开发库的结构管理权限，不是生产权限方案。初始化失败时已创建资源会保留，需人工检查。

完成后，`python start.py` 和 `python migrate.py` 读取项目根目录 `.env` 中的数据库连接信息和 `WELLSPRING_DB_PASSWORD`。可参照 [.env.example](.env.example) 设置；实际 `.env` 包含密码，不纳入仓库或源码包。旧 `.wellspring-postgres.json` 在 `.env` 不存在时会自动迁移非密码参数，需自行填写密码；若显式设置 `DATABASE_URL`，以该变量为准。切换数据库不会迁移已有账号或数据，PostgreSQL 管理员账号需在新库中单独初始化。

迁移入口统一命名为 `migrate.py`，环境由配置和凭据区分，后续生产阶段无须再改名。旧 `migrate_dev.py` 保留转发兼容；离线部署继续使用独立 `migrate` 容器任务及迁移所有者账号，详见部署说明。

### 首次安装

在 PowerShell 中执行一次：

```powershell
cd E:\wellspring\backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --require-hashes -r requirements-dev.lock
cd E:\wellspring
python migrate.py
python migrate.py --bootstrap

cd E:\wellspring\frontend
npm ci
```

创建开发账号时，按提示输入账号、组织和至少 12 位的密码。如果已有账号，无须重复执行 `bootstrap`。

### 一键启动

```powershell
cd E:\wellspring
python start.py
```

保持该终端窗口打开，访问 [http://127.0.0.1:5173](http://127.0.0.1:5173)；按 `Ctrl+C` 停止本次启动的前后端。前端支持 Vite 热更新；修改后端代码后需停止并重新运行启动脚本。

启动器会在启动服务前检查数据库版本。已有库只自动执行明确标记 `startup_safe = True` 的待执行迁移，加锁并完成迁移前备份，升级成功后才启动；无迁移时不改库。未标记迁移、备份失败、未知版本或上次中断会停止启动，需停服检查后在根目录执行 `python migrate.py`。全新空库可自动初始化，但账号仍需显式创建。`--no-auto-migrate` 可切回仅检查模式。启动器不会自动安装依赖或终止已有服务。若默认端口已被其他进程占用，先自行停止对应服务，或使用其他端口：

```powershell
python start.py --backend-port 8001 --frontend-port 5174
```

前端会自动代理到所指定的后端端口。访问令牌保存在当前浏览器标签页的会话存储中，刷新后会向服务端验证并恢复登录；退出、关闭标签页或服务端会话失效后需要重新登录。该启动器仅供本地开发，生产部署仍需单独设计。

运行检查：`cd backend; .\.venv\Scripts\python.exe -m pytest -q`；项目根目录 `python migrate.py --check`；`cd frontend; npm test; npm run build; npm run test:e2e`。浏览器回归使用自动创建的临时 SQLite 和合成账号，首次需执行 `npx playwright install chromium`。PostgreSQL 专项测试需显式设置指向隔离服务器的 `TEST_DATABASE_URL`，会新建随机测试库，不能用普通 `DATABASE_URL` 代替。GitHub Actions 已配置 PostgreSQL 17/18、浏览器及依赖检查；尚无远程运行结果或分支保护。

## 明确缺口及后续工作

使用新功能前，停止旧版后端；已有数据库若仍需执行 `0017` 或更早的数据变更，应在项目根目录运行 `python migrate.py` 显式升级（自动先备份），核对数据库目标后再启动。`0017` 将 SQLite 重量转换为精确十进制文本，遇非法历史值会停止；已丢失的浮点精度无法恢复，也不提供会丢失精度的 SQLite 降级，回退需恢复已验证备份。`0018` 新增索引，可由受控启动流程自动执行。此前迁移会将初始管理员 `admin` 归入“系统运维”组织，不改变历史业务数据的所属组织；尚按组织过滤的模块可能不再显示原组织记录。页面只在内存保留未确认请求的幂等键，刷新或退出后应先核对结果，不能盲目重发。

当前已有账号、角色、权限目录和组织管理，以及模块操作授权和会话撤销；**不等于正式生产权限验收**。正式岗位矩阵、字段权限、专案/跨组织授权、PostgreSQL RLS、独立受保护审计和统一认证仍待建设。已增加进程级登录节流、请求预算、依赖哈希锁及恢复测试；多进程部署仍需共享网关限流。生产部署、HTTPS、目标环境完整恢复、离线制品及供应链验收仍未完成。

证物仅支持初始登记和分样；已为开发写接口增加幂等记录，但尚无正式岗位复核、实物交接、送检、消耗、退样、盘点差异正式审批及调整、销毁、附件或完整账实核对；不得据此保管实物或计算正式账目。线索工单仅具备开发验证的组织隔离和简化流程，尚无正式岗位权限、自动期限规则及跨区协作；案件派生／并案／拆分、人员身份核验及措施事件、精确碰撞、正式人员／证物关联、Excel 正式导入、文书 AI 解析和正式检索均未实现。页面上的未实现模块不代表已交付能力。

下一步应依据方案第 9.2 节完成阶段 0 签字材料及环境验证，再以经批准的权限和业务规则实现首期全流程，补齐 PostgreSQL 并发与 RLS、恢复和安全测试，按方案完成生产加固和验收。精度、时限及法律状态不能由开发人员自行确认。
